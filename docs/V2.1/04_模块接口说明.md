# RM SuperCap Controller V2.1 模块接口说明

## 1. 文档目的

本文档用于冻结 RM SuperCap Controller V2.1 的模块接口设计原则、模块职责边界、共享数据访问规则、Reset 粒度、RunMode 切换时序、FaultManager 与 StateMachine 职责边界，以及 Driver 层接口约束。

本文档是后续编写各模块 `.h/.c` 文件的接口依据。

---

## 2. 模块分层

V2.1 软件模块按以下层次组织：

```text
Application Layer
├── supercap_app
├── state_machine
└── mode_manager

Control Layer
├── power_manager
├── charge_manager
├── discharge_manager
├── voltage_manager
├── pi_controller
└── fsbb_modulator

Protection Layer
└── fault_manager

Protocol Layer
├── can_protocol
└── debug_protocol

Driver Layer
├── adc_driver / adc_manager
├── pwm_driver
├── hrtim_pwm
├── can_driver
└── gpio_driver

Config Layer
├── supercap_types.h
└── supercap_param.h
```

设计约束：

```text
1. Application Layer 负责系统调度和模块协作。
2. Control Layer 负责控制算法和参考值计算。
3. Protection Layer 负责故障检测和故障标志维护。
4. Protocol Layer 负责协议解析、打包和调试数据组织。
5. Driver Layer 只负责底层硬件动作，不理解系统业务状态。
6. Config Layer 集中保存类型、枚举、参数和宏定义。
```

---

## 3. 模块接口冻结原则

V2.1 模块接口设计冻结以下 11 条原则：

```text
1. 上层模块统一通过 SuperCapContext_t 传递系统上下文。

2. StateMachine 只负责 system_state，不直接操作 PWM。

3. ModeManager 只负责提出 run_mode 切换请求，
   不直接清 PI，不直接操作 PWM。

4. SuperCapApp 作为唯一总调度者，
   统一执行 Reset、AllOff、Disable 动作。

5. PowerManager 内部使用 ChargePowerPI 与 DischargePowerPI 两个功率环实例。

6. PwmDriver_SetDuty 只写 preload / shadow register，
   PwmDriver_AllOff 立即关断 PWM。

7. ISR 与慢环共享数据管理放在 1 kHz SlowLoop 中统一处理，
   CAN / Debug 不直接读取 ctx，而是读取 1 kHz SlowLoop 生成的双缓冲 Snapshot。

8. Reset 粒度分为：
   ResetAll、ResetAllPi、ResetOldModeController、ResetForFault、ResetAfterClearFault。

9. RunMode 切换顺序固定为：
   关旧 PWM -> 清旧方向 PI -> 提交新 run_mode -> 新方向快环输出。

10. FaultManager 只维护 fault flag / fault_code，
    StateMachine 只根据 fault 状态、enable、clear_fault 决定 system_state。

11. Driver 层不允许读取 SuperCapContext_t，
    Driver 层只接受明确参数，例如 FsbbDuty_t、raw buffer、CAN data。
```

## 4. SuperCapContext_t 使用原则

### 4.1 冻结结论

上层业务模块统一通过 `SuperCapContext_t *ctx` 传递系统上下文。

典型接口：

```c
void SuperCapApp_Init(SuperCapContext_t *ctx);
void SuperCapApp_FastLoop100kHz(SuperCapContext_t *ctx);
void SuperCapApp_SlowLoop1kHz(SuperCapContext_t *ctx);
void PowerManager_Update1kHz(SuperCapContext_t *ctx);
void ChargeManager_UpdateCurrentLoop100kHz(SuperCapContext_t *ctx);
void DischargeManager_UpdateCurrentLoop100kHz(SuperCapContext_t *ctx);
void FaultManager_SlowUpdate1kHz(SuperCapContext_t *ctx);
```

### 4.2 建议结构

```c
typedef struct
{
    SuperCapCmd_t cmd;
    SuperCapMeas_t meas;
    SuperCapStatus_t status;

    PowerManager_t power;
    VoltageManager_t voltage;
    ChargeManager_t charge;
    DischargeManager_t discharge;
    FaultManager_t fault;

    SuperCapSnapshotBuffer_t snapshot_buf;
} SuperCapContext_t;
```

### 4.3 使用限制

```text
1. Application / Control / Protection / Protocol 层可以读取 ctx。
2. Driver 层不允许读取 ctx。
3. 快环 ISR 只访问必要字段。
4. CAN / Debug 不直接读取 ctx，而是读取 Snapshot。
```

## 5. ISR 与慢环共享数据访问规则

### 5.1 冻结结论

不新建独立的 `DataSyncTask`。

共享数据管理统一放在：

```text
1 kHz SlowLoop
```

CAN / Debug 不直接读取 `SuperCapContext_t`，而是读取 1 kHz SlowLoop 生成的双缓冲 Snapshot。

### 5.2 任务分工

```text
100 kHz ADC ISR:
- 更新 fast ADC 测量量
- 快速过流检测
- 电流环
- FSBB 调制
- PWM shadow 更新

1 kHz SlowLoop:
- 更新 slow ADC 测量量
- Fault 状态处理
- StateMachine
- ModeManager
- PowerManager
- VoltageManager
- 生成双缓冲 Snapshot

10 ms CAN Task:
- 读取 Snapshot
- 打包并发送 CAN

20 ms Debug Task:
- 读取 Snapshot
- 输出 Debug
```

### 5.3 数据写入归属

| 数据 | 写入位置 | 读取位置 | 说明 |
|---|---|---|---|
| `meas.fast` | 100 kHz ISR | 电流环、Fault 快检、1 kHz Snapshot | 快速 ADC 量 |
| `meas.slow` | 1 kHz SlowLoop | PowerManager、CAN/Debug Snapshot | 慢速功率量 |
| `status.system_state` | 1 kHz SlowLoop | 100 kHz ISR、Snapshot | ISR 只读 |
| `status.run_mode` | SuperCapApp 在 1 kHz SlowLoop 中提交 | 100 kHz ISR、Snapshot | ISR 只读 |
| `status.requested_run_mode` | ModeManager | SuperCapApp | 模式切换请求 |
| `power.p_charge_ref` | 1 kHz SlowLoop | 100 kHz ISR、Snapshot | ISR 只读 |
| `power.p_discharge_ref` | 1 kHz SlowLoop | 100 kHz ISR、Snapshot | ISR 只读 |
| `charge.i_ref` | 1 kHz SlowLoop | 100 kHz ISR、Snapshot | ISR 只读 |
| `discharge.i_phase_ref` | 1 kHz SlowLoop | 100 kHz ISR、Snapshot | ISR 只读 |
| `fault.oc_flag` | 100 kHz ISR | 1 kHz FaultManager | ISR 置位，慢环消费 |
| `fault.fault_code` | FaultManager | StateMachine、Snapshot | 慢环维护 |
| `snapshot_buf` | 1 kHz SlowLoop | CAN / Debug | 双缓冲快照 |

### 5.4 Snapshot 结构建议

```c
typedef struct
{
    SuperCapCmd_t cmd;
    SuperCapMeas_t meas;
    SuperCapStatus_t status;

    float p_input;
    float p_chassis;
    float p_error;

    float p_charge_ref;
    float p_discharge_ref;

    float i_charge_ref;
    float i_phase_ref;

    float dg_comp_charge;
    float dg_comp_a;
    float dg_comp_b;

    FaultCode_t fault_code;
} SuperCapSnapshot_t;
```

### 5.5 双缓冲 Snapshot

```c
typedef struct
{
    SuperCapSnapshot_t buf[2];
    volatile uint8_t active_index;
} SuperCapSnapshotBuffer_t;
```

1 kHz SlowLoop 写 inactive buffer：

```c
void SuperCapApp_UpdateSnapshot1kHz(SuperCapContext_t *ctx)
{
    uint8_t inactive = ctx->snapshot_buf.active_index ^ 1U;
    SuperCapSnapshot_t *snap = &ctx->snapshot_buf.buf[inactive];

    snap->cmd = ctx->cmd;
    snap->meas = ctx->meas;
    snap->status = ctx->status;

    snap->p_input = ctx->meas.slow.p_input;
    snap->p_chassis = ctx->meas.slow.p_chassis;
    snap->p_error = ctx->power.p_error;

    snap->p_charge_ref = ctx->power.p_charge_ref;
    snap->p_discharge_ref = ctx->power.p_discharge_ref;

    snap->i_charge_ref = ctx->charge.i_ref;
    snap->i_phase_ref = ctx->discharge.i_phase_ref;

    snap->dg_comp_charge = ctx->charge.dg_comp;
    snap->dg_comp_a = ctx->discharge.dg_comp_a;
    snap->dg_comp_b = ctx->discharge.dg_comp_b;

    snap->fault_code = ctx->fault.fault_code;

    __disable_irq();
    ctx->snapshot_buf.active_index = inactive;
    __enable_irq();
}
```

CAN / Debug 读取 active buffer：

```c
const SuperCapSnapshot_t *SuperCapApp_GetSnapshot(const SuperCapContext_t *ctx)
{
    return &ctx->snapshot_buf.buf[ctx->snapshot_buf.active_index];
}
```

### 5.6 设计要求

```text
1. CAN / Debug 只能读 Snapshot，不直接读 ctx。
2. 1 kHz SlowLoop 负责生成 Snapshot。
3. 双缓冲只在切换 active_index 时短暂关中断。
4. 不允许 CAN / Debug 一边读取 ctx 一边格式化数据。
```

## 6. Reset 粒度设计

### 6.1 冻结结论

Reset 不使用单一函数处理全部场景，而是划分为 5 个粒度：

```text
1. ResetAll
2. ResetAllPi
3. ResetOldModeController
4. ResetForFault
5. ResetAfterClearFault
```

### 6.2 ResetAll

用途：初始化或彻底重置系统。

```c
void SuperCapApp_ResetAll(SuperCapContext_t *ctx);
```

动作：

```text
PWM_AllOff
清所有 PI
清功率参考
清电流参考
清 Dg_comp
清 Fault 计数
清 CAP_OV 计数
清 run_mode_changed / run_mode_change_request
恢复默认 power_limit
```

### 6.3 ResetAllPi

用途：进入非 RUNNING 状态时，只清控制器积分。

```c
void SuperCapApp_ResetAllPi(SuperCapContext_t *ctx);
```

动作：

```text
清 ChargePowerPI
清 DischargePowerPI
清 VoltagePI
清 ChargeCurrentPI
清 DischargeCurrentPI_A
清 DischargeCurrentPI_B
```

不清：

```text
fault_code
cap_ov_count
system_state
run_mode
power_limit
```

### 6.4 ResetOldModeController

用途：RunMode 切换时只清旧方向控制器。

```c
void SuperCapApp_ResetOldModeController(SuperCapContext_t *ctx,
                                        RunMode_t old_mode);
```

动作：

```text
CHARGE -> DISCHARGE:
    清 ChargePowerPI
    清 ChargeCurrentPI
    清 I_charge_ref
    清 Dg_comp_charge

DISCHARGE -> CHARGE:
    清 DischargePowerPI
    清 DischargeCurrentPI_A
    清 DischargeCurrentPI_B
    清 I_phase_ref
    清 Dg_comp_A / Dg_comp_B
```

### 6.5 ResetForFault

用途：进入 Fault / CAP_OV_RECOVER / DISABLED 时使用。

```c
void SuperCapApp_ResetForFault(SuperCapContext_t *ctx);
```

动作：

```text
PWM_AllOff
清所有 PI
清所有电流参考
清所有 Dg_comp
保留 fault_code
保留 cap_ov_count
保留 system_state
保留 power_limit
```

### 6.6 ResetAfterClearFault

用途：锁死故障被主控 clear_fault 成功清除后使用。

```c
void SuperCapApp_ResetAfterClearFault(SuperCapContext_t *ctx);
```

动作：

```text
清 fault_code
清 latched fault flag
清 cap_ov_count
清 cap_ov_event_latched
清所有 PI
清所有电流参考
PWM 保持关闭，等待状态机重新进入 RUNNING
```

## 7. RunMode 切换时序

### 7.1 冻结结论

RunMode 切换顺序固定为：

```text
关旧 PWM -> 清旧方向 PI -> 提交新 run_mode -> 新方向快环输出
```

### 7.2 状态字段建议

```c
typedef struct
{
    SystemState_t system_state;

    RunMode_t run_mode;
    RunMode_t requested_run_mode;
    RunMode_t last_run_mode;

    bool run_mode_change_request;
    bool run_mode_changed;

    FaultCode_t fault_code;
    uint8_t cap_ov_count;
    bool low_cap_lock;
} SuperCapStatus_t;
```

### 7.3 ModeManager 职责

ModeManager 只判断目标方向，不执行切换动作。

```text
1. 根据 P_error 和 low_cap_lock 计算 requested_run_mode。
2. 如果 requested_run_mode != run_mode，置位 run_mode_change_request。
3. 不清 PI。
4. 不关闭 PWM。
5. 不直接修改 run_mode。
```

### 7.4 SuperCapApp 切换流程

```text
1. 检测 run_mode_change_request。
2. 记录 old_mode = run_mode。
3. 调用 PwmDriver_DisableCharge() 或 PwmDriver_DisableDischarge() 关闭旧方向 PWM。
4. 调用 SuperCapApp_ResetOldModeController(ctx, old_mode) 清旧方向 PI 和参考值。
5. 提交 run_mode = requested_run_mode。
6. 更新 last_run_mode。
7. 清 run_mode_change_request。
8. 置位 run_mode_changed，供 Debug / Snapshot 使用。
9. 新方向在下一次 100 kHz ISR 中直接闭环输出。
```

### 7.5 注意事项

```text
1. 切换过程中不进入 IDLE。
2. 切换过程中不执行软启动。
3. 旧方向 PWM 必须先关闭。
4. 新方向 PWM 由快环按已提交 run_mode 输出。
5. 切换请求只在 SYS_RUNNING 状态下处理。
```

## 8. FaultManager 与 StateMachine 职责边界

### 8.1 冻结结论

```text
FaultManager 只负责故障检测、fault flag 和 fault_code。
StateMachine 只负责根据 fault 状态、enable、clear_fault 决定 system_state。
```

FaultManager 不直接修改：

```text
ctx->status.system_state
```

StateMachine 不直接检测 ADC，不计算电流，不计算功率，不直接操作 PWM。

### 8.2 FaultManager 职责

FaultManager 负责：

```text
1. 检测输入欠压。
2. 检测严重输入欠压。
3. 检测输入过压。
4. 检测 CAP_OV。
5. 维护 cap_ov_count。
6. 检测轻度过流。
7. 检测严重过流。
8. 检测 HRTIM Brake。
9. 维护 fault_code。
10. 维护 fault flags。
11. 判断故障条件是否消失。
```

建议结构：

```c
typedef struct
{
    bool input_uv;
    bool input_severe_uv;
    bool input_ov;

    bool cap_ov_recover;
    bool cap_ov_latched;

    bool oc_recoverable;
    bool oc_latched;

    bool hrtim_brake;

    bool any_recoverable_fault;
    bool any_latched_fault;

    FaultCode_t fault_code;

    uint16_t oc_recoverable_cnt;
    uint16_t oc_latched_cnt;
    uint16_t fault_recover_stable_cnt;

    uint8_t cap_ov_count;
    bool cap_ov_event_latched;
} FaultManager_t;
```

### 8.3 StateMachine 职责

StateMachine 读取：

```text
ctx->cmd.enable
ctx->cmd.clear_fault
ctx->fault.any_recoverable_fault
ctx->fault.any_latched_fault
ctx->fault.cap_ov_recover
ctx->fault.fault_recover_stable_cnt
```

StateMachine 决定：

```text
SYS_DISABLED
SYS_RUNNING
SYS_CAP_OV_RECOVER
SYS_FAULT_RECOVERABLE
SYS_FAULT_LATCHED
```

### 8.4 clear_fault 职责分工

```text
1. CANProtocol 只解析 clear_fault 命令。
2. StateMachine 判断 clear_fault 是否处于有效状态。
3. FaultManager 判断当前故障条件是否已经消失。
4. SuperCapApp 在 clear_fault 成功后调用 ResetAfterClearFault。
```

## 9. Driver 层接口约束

### 9.1 冻结结论

Driver 层不允许读取 `SuperCapContext_t *ctx`。

Driver 层只接受明确参数。

### 9.2 PWM Driver

允许接口：

```c
void PwmDriver_SetChargeDuty(const FsbbDuty_t *duty);
void PwmDriver_SetDischargeDutyA(const FsbbDuty_t *duty);
void PwmDriver_SetDischargeDutyB(const FsbbDuty_t *duty);
void PwmDriver_AllOff(void);
void PwmDriver_DisableCharge(void);
void PwmDriver_DisableDischarge(void);
```

不允许：

```c
void PwmDriver_Update(SuperCapContext_t *ctx);
```

### 9.3 ADC Driver

允许接口：

```c
void AdcDriver_StartInjected(void);
void AdcDriver_GetInjectedRaw(uint16_t *raw_buf);
void AdcDriver_GetRegularRaw(uint16_t *raw_buf);
```

不允许：

```c
void AdcDriver_Update(SuperCapContext_t *ctx);
```

说明：

```text
ADC Driver 只提供 raw 数据。
ADCManager 可以读取 raw 数据并更新 ctx->meas。
```

### 9.4 CAN Driver

允许接口：

```c
bool CanDriver_Send(uint32_t id, const uint8_t *data, uint8_t dlc);
bool CanDriver_Read(uint32_t *id, uint8_t *data, uint8_t *dlc);
```

不允许：

```c
void CanDriver_SendStatus(SuperCapContext_t *ctx);
```

说明：

```text
CAN Driver 只负责底层收发。
CanProtocol 负责协议解析和打包。
```

### 9.5 HRTIM Driver

允许接口：

```c
void HrtimPwm_StartAllTimers(void);
void HrtimPwm_EnableOutputs(void);
void HrtimPwm_DisableOutputs(void);
void HrtimPwm_SetCompareShadow(...);
```

不允许：

```c
void HrtimPwm_RunStateMachine(SuperCapContext_t *ctx);
```
