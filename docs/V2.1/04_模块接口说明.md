# RM SuperCap Controller V2.1 模块接口说明

## 1. 文档目的

本文档用于冻结 RM SuperCap Controller V2.1 的模块接口设计原则、公共类型、模块结构体、模块职责边界、共享数据访问规则、Reset 粒度、RunMode 切换时序、FaultManager 与 StateMachine 职责边界，以及各模块 `.h` API。

本文档是后续编写各模块 `.h/.c` 文件的接口依据。

---

## 2. 模块分层

V2.1 软件模块按以下层次组织：

```text
Application Layer
├── supercap_app
├── state_machine
└── mode_manager

Control Layer
├── power_manager
├── voltage_manager
├── charge_manager
├── discharge_manager
├── pi_controller
└── fsbb_modulator

Protection Layer
└── fault_manager

Protocol Layer
├── can_protocol
└── debug_protocol

Driver Layer
├── adc_driver / adc_manager
├── pwm_driver
├── hrtim_pwm
├── can_driver
├── uart_driver
└── gpio_driver

Config Layer
├── supercap_types.h
└── supercap_param.h
```

设计约束：

```text
1. Application Layer 负责系统调度和模块协作。
2. Control Layer 负责控制算法和参考值计算。
3. Protection Layer 负责故障检测和故障标志维护。
4. Protocol Layer 负责协议解析、打包和调试数据组织。
5. Driver Layer 只负责底层硬件动作，不理解系统业务状态。
6. Config Layer 集中保存类型、枚举、参数和宏定义。
```

---

## 3. 模块接口冻结原则

V2.1 模块接口设计冻结以下 11 条原则：

```text
1. 上层模块统一通过 SuperCapContext_t 传递系统上下文。

2. StateMachine 只负责 system_state，不直接操作 PWM。

3. ModeManager 只负责提出 run_mode 切换请求，
   不直接清 PI，不直接操作 PWM。

4. SuperCapApp 作为唯一总调度者，
   统一执行 Reset、AllOff、Disable 动作。

5. PowerManager 内部使用 ChargePowerPI 与 DischargePowerPI 两个功率环实例。

6. PwmDriver_SetDuty 只写 preload / shadow register，
   PwmDriver_AllOff 立即关断 PWM。

7. ISR 与慢环共享数据管理放在 1 kHz SlowLoop 中统一处理，
   CAN / Debug 不直接读取 ctx，而是读取 1 kHz SlowLoop 生成的双缓冲 Snapshot。

8. Reset 粒度分为：
   ResetAll、ResetAllPi、ResetOldModeController、ResetForFault、ResetAfterClearFault。

9. RunMode 切换顺序固定为：
   关旧 PWM -> 清旧方向 PI -> 提交新 run_mode -> 新方向快环输出。

10. FaultManager 只维护 fault flag / fault_code，
    StateMachine 只根据 fault 状态、enable、clear_fault 决定 system_state。

11. Driver 层不允许读取 SuperCapContext_t，
    Driver 层只接受明确参数，例如 FsbbDuty_t、raw buffer、CAN data。
```

```c
typedef enum
```

Snapshot 使用精简版，不重复保存 `p_input`、`p_chassis` 和 `fault_code`。

```c
    float p_discharge_ref;

    float i_phase_ref;

    float dg_comp_charge;
    float dg_comp_a;
    float dg_comp_b;
} SuperCapSnapshot_t;
```

```c
typedef struct
{
    SuperCapSnapshot_t buf[2];
    volatile uint8_t active_index;
} SuperCapSnapshotBuffer_t;
```

冻结原则：

```text
1. meas.slow.p_input / meas.slow.p_chassis 已经包含功率值，不在 Snapshot 顶层重复。
2. status.fault_code 已经包含故障码，不在 Snapshot 顶层重复。
3. Snapshot 只服务 CAN / Debug / 日志，不参与控制闭环。
4. Snapshot 由 1 kHz SlowLoop 生成。
5. CAN / Debug 只读 active Snapshot。
```

## 5. Manager 结构体冻结

### 5.1 PowerManager_t

```c
typedef struct
{
    PI_Controller_t charge_power_pi;
    PI_Controller_t discharge_power_pi;

    float p_input;
    float p_chassis;
    float p_error;

    float p_charge_ref;
    float p_discharge_ref;

    float p_charge_max;
    float p_discharge_max;
} PowerManager_t;
```

冻结原则：

```text
1. PowerManager 计算 p_input、p_chassis、p_error。
2. p_error = power_limit - p_input。
3. PowerManager 内部使用 ChargePowerPI 和 DischargePowerPI 两个 PI。
4. PowerManager 输出 p_charge_ref / p_discharge_ref，单位 W。
5. PowerManager 不直接输出电流参考。
6. 充电电流参考由 ChargeManager 计算。
7. 放电电流参考由 DischargeManager 计算。
8. 放电最大功率第一版固定为 500 W。
```

### 5.2 VoltageManager_t

```c
typedef struct
{
    PI_Controller_t voltage_pi;

    float v_cap_target;
    float v_error;

    float i_charge_cv_limit;

    float i_charge_cv_min;
    float i_charge_cv_max;
} VoltageManager_t;
```

冻结原则：

```text
1. VoltageManager 只做超级电容恒压限制。
2. 默认目标电压 v_cap_target = 30 V。
3. 电压误差 v_error = v_cap_target - v_cap。
4. Voltage PI 输出 i_charge_cv_limit，单位 A。
5. i_charge_cv_limit 只作为 ChargeManager 计算 i_ref 时的上限。
6. VoltageManager 不直接修改 Dg。
7. VoltageManager 不直接控制 PWM。
8. VoltageManager 只在充电方向有效。
9. 第一版 i_charge_cv_limit 建议限幅 0 ~ 10 A。
```

### 5.3 ChargeManager_t

```c
typedef struct
{
    PI_Controller_t current_pi;

    float i_ref;
    float i_error;

    float i_ref_from_power;
    float i_ref_from_output_limit;
    float i_ref_from_cv_limit;
    float i_ref_from_hw_limit;

    float dg_comp;

    FsbbDuty_t duty;
} ChargeManager_t;
```

冻结原则：

```text
1. ChargeManager 负责生成最终 i_ref。
2. i_ref 是唯一最终充电电流参考，不再单独保留 i_ref_final。
3. i_ref = min(功率电流限制、输出电流限制、恒压限流、硬件限流)。
4. ChargeManager_UpdateRef1kHz() 计算 i_ref。
5. ChargeManager_UpdateCurrentLoop100kHz() 计算 i_error、dg_comp 和 duty。
6. 电流反馈使用 I_charge_ADC。
7. ChargeManager 不直接写 PWM。
8. PWM 输出由 SuperCapApp / 快环调用 PwmDriver_SetChargeDuty() 完成。
```

### 5.4 DischargeManager_t

```c
typedef struct
{
    PI_Controller_t current_pi_a;
    PI_Controller_t current_pi_b;

    float i_total_ref;
    float i_phase_ref;

    float i_error_a;
    float i_error_b;

    float dg_comp_a;
    float dg_comp_b;

    FsbbDuty_t duty_a;
    FsbbDuty_t duty_b;
} DischargeManager_t;
```

冻结原则：

```text
1. DischargeManager 负责生成 i_total_ref 和 i_phase_ref。
2. i_total_ref = p_discharge_ref / v_chassis。
3. i_phase_ref = i_total_ref / 2。
4. 第一版不加入 current_balance_loop。
5. A/B 两相分别使用独立 Current PI。
6. A 相反馈使用 average_I_phase1_ADC。
7. B 相反馈使用 average_I_phase2_ADC。
8. Io_phase1 / Io_phase2 不作为第一版闭环反馈，只用于保护、上报和调试。
9. DischargeManager_UpdateCurrentLoop100kHz() 计算 A/B 两相 dg_comp 和 duty。
10. DischargeManager 不直接写 PWM。
```

### 5.5 FaultManager_t

```c
typedef struct
{
    bool input_uv;
    bool input_severe_uv;
    bool input_ov;

    bool cap_ov_recover;
    bool cap_ov_latched;
    bool cap_ov_event_latched;

    bool charge_oc_recoverable;
    bool charge_oc_latched;

    bool discharge_phase_a_oc_recoverable;
    bool discharge_phase_a_oc_latched;

    bool discharge_phase_b_oc_recoverable;
    bool discharge_phase_b_oc_latched;

    bool discharge_total_oc_recoverable;
    bool discharge_total_oc_latched;

    bool hrtim_brake;

    bool any_recoverable_fault;
    bool any_latched_fault;

    FaultCode_t fault_code;

    uint16_t charge_oc_recoverable_cnt;
    uint16_t charge_oc_latched_cnt;

    uint16_t discharge_phase_a_oc_recoverable_cnt;
    uint16_t discharge_phase_a_oc_latched_cnt;

    uint16_t discharge_phase_b_oc_recoverable_cnt;
    uint16_t discharge_phase_b_oc_latched_cnt;

    uint16_t discharge_total_oc_recoverable_cnt;
    uint16_t discharge_total_oc_latched_cnt;

    uint16_t fault_recover_stable_cnt;

    uint8_t cap_ov_count;
} FaultManager_t;
```

冻结原则：

```text
1. FaultManager 不直接修改 system_state。
2. FaultManager 维护 fault flags、fault_code、cap_ov_count 和过流计数。
3. CAP_OV_RECOVER 独立于普通 recoverable fault。
4. HRTIM Brake 直接进入 latched fault。
5. fault_code 用于 CAN / Debug 上报。
6. any_recoverable_fault / any_latched_fault 用于 StateMachine 判断。
7. clear_fault 是否有效由 StateMachine + FaultManager_IsFaultGone() 共同判断。
```

## 6. ISR 与慢环共享数据访问规则

### 6.1 冻结结论

不新建独立的 `DataSyncTask`。

共享数据管理统一放在：

```text
1 kHz SlowLoop
```

CAN / Debug 不直接读取 `SuperCapContext_t`，而是读取 1 kHz SlowLoop 生成的双缓冲 Snapshot。

### 6.2 任务分工

```text
100 kHz ADC ISR:
- 更新 fast ADC 测量量
- 快速过流检测
- 电流环
- FSBB 调制
- PWM shadow 更新

1 kHz SlowLoop:
- 更新 slow ADC 测量量
- Fault 状态处理
- StateMachine
- ModeManager
- PowerManager
- VoltageManager
- 生成双缓冲 Snapshot

10 ms CAN Task:
- 读取 Snapshot
- 打包并发送 CAN

20 ms Debug Task:
- 读取 Snapshot
- 输出 VOFA Debug
```

### 6.3 数据写入归属

| 数据 | 写入位置 | 读取位置 | 说明 |
|---|---|---|---|
| `meas.fast` | 100 kHz ISR | 电流环、Fault 快检、1 kHz Snapshot | 快速 ADC 量 |
| `meas.slow` | 1 kHz SlowLoop | PowerManager、CAN/Debug Snapshot | 慢速功率量 |
| `status.system_state` | 1 kHz SlowLoop | 100 kHz ISR、Snapshot | ISR 只读 |
| `status.run_mode` | SuperCapApp 在 1 kHz SlowLoop 中提交 | 100 kHz ISR、Snapshot | ISR 只读 |
| `status.requested_run_mode` | ModeManager | SuperCapApp | 模式切换请求 |
| `power.p_charge_ref` | 1 kHz SlowLoop | 100 kHz ISR、Snapshot | ISR 只读 |
| `power.p_discharge_ref` | 1 kHz SlowLoop | 100 kHz ISR、Snapshot | ISR 只读 |
| `charge.i_ref` | 1 kHz SlowLoop | 100 kHz ISR、Snapshot | ISR 只读 |
| `discharge.i_phase_ref` | 1 kHz SlowLoop | 100 kHz ISR、Snapshot | ISR 只读 |
| `fault.oc_flag` | 100 kHz ISR | 1 kHz FaultManager | ISR 置位，慢环消费 |
| `fault.fault_code` | FaultManager | StateMachine、Snapshot | 慢环维护 |
| `snapshot_buf` | 1 kHz SlowLoop | CAN / Debug | 双缓冲快照 |

### 6.4 双缓冲 Snapshot 更新接口

```c
void SuperCapApp_UpdateSnapshot1kHz(SuperCapContext_t *ctx);

const SuperCapSnapshot_t *SuperCapApp_GetSnapshot(const SuperCapContext_t *ctx);
```

设计要求：

```text
1. CAN / Debug 只能读 Snapshot，不直接读 ctx。
2. 1 kHz SlowLoop 负责生成 Snapshot。
3. 双缓冲只在切换 active_index 时短暂关中断。
4. 不允许 CAN / Debug 一边读取 ctx 一边格式化数据。
```

## 7. Reset 粒度设计

Reset 划分为 5 个粒度：

```text
1. ResetAll
2. ResetAllPi
3. ResetOldModeController
4. ResetForFault
5. ResetAfterClearFault
```

### 7.1 ResetAll

用途：初始化或彻底重置系统。

```c
void SuperCapApp_ResetAll(SuperCapContext_t *ctx);
```

动作：

```text
PWM_AllOff
清所有 PI
清功率参考
清电流参考
清 Dg_comp
清 Fault 计数
清 CAP_OV 计数
清 run_mode_changed / run_mode_change_request
恢复默认 power_limit
```

### 7.2 ResetAllPi

用途：进入非 RUNNING 状态时，只清控制器积分。

```c
void SuperCapApp_ResetAllPi(SuperCapContext_t *ctx);
```

不清：

```text
fault_code
cap_ov_count
system_state
run_mode
power_limit
```

### 7.3 ResetOldModeController

用途：RunMode 切换时只清旧方向控制器。

```c
void SuperCapApp_ResetOldModeController(SuperCapContext_t *ctx,
                                        RunMode_t old_mode);
```

动作：

```text
CHARGE -> DISCHARGE:
    清 ChargePowerPI
    清 ChargeCurrentPI
    清 I_charge_ref
    清 Dg_comp_charge

DISCHARGE -> CHARGE:
    清 DischargePowerPI
    清 DischargeCurrentPI_A
    清 DischargeCurrentPI_B
    清 I_phase_ref
    清 Dg_comp_A / Dg_comp_B
```

### 7.4 ResetForFault

用途：进入 Fault / CAP_OV_RECOVER / DISABLED 时使用。

```c
void SuperCapApp_ResetForFault(SuperCapContext_t *ctx);
```

动作：

```text
PWM_AllOff
清所有 PI
清所有电流参考
清所有 Dg_comp
保留 fault_code
保留 cap_ov_count
保留 system_state
保留 power_limit
```

### 7.5 ResetAfterClearFault

用途：锁死故障被主控 clear_fault 成功清除后使用。

```c
void SuperCapApp_ResetAfterClearFault(SuperCapContext_t *ctx);
```

动作：

```text
清 fault_code
清 latched fault flag
清 cap_ov_count
清 cap_ov_event_latched
清所有 PI
清所有电流参考
PWM 保持关闭，等待状态机重新进入 RUNNING
```

## 8. RunMode 切换时序

RunMode 切换顺序固定为：

```text
关旧 PWM -> 清旧方向 PI -> 提交新 run_mode -> 新方向快环输出
```

ModeManager 只判断目标方向，不执行切换动作。

```text
1. 根据 p_error 和 low_cap_lock 计算 requested_run_mode。
2. 如果 requested_run_mode != run_mode，置位 run_mode_change_request。
3. 不清 PI。
4. 不关闭 PWM。
5. 不直接修改 run_mode。
```

SuperCapApp 切换流程：

```text
1. 检测 run_mode_change_request。
2. 记录 old_mode = run_mode。
3. 关闭旧方向 PWM。
4. 调用 SuperCapApp_ResetOldModeController(ctx, old_mode)。
5. 提交 run_mode = requested_run_mode。
6. 更新 last_run_mode。
7. 清 run_mode_change_request。
8. 置位 run_mode_changed，供 Debug / Snapshot 使用。
9. 新方向在下一次 100 kHz ISR 中直接闭环输出。
```

注意事项：

```text
1. 切换过程中不进入 IDLE。
2. 切换过程中不执行软启动。
3. 旧方向 PWM 必须先关闭。
4. 新方向 PWM 由快环按已提交 run_mode 输出。
5. 切换请求只在 SYS_RUNNING 状态下处理。
```

## 9. FaultManager 与 StateMachine 职责边界

冻结结论：

```text
FaultManager 只负责故障检测、fault flag 和 fault_code。
StateMachine 只负责根据 fault 状态、enable、clear_fault 决定 system_state。
```

FaultManager 不直接修改：

```text
ctx->status.system_state
```

StateMachine 不直接检测 ADC，不计算电流，不计算功率，不直接操作 PWM。

clear_fault 职责分工：

```text
1. CANProtocol 只解析 clear_fault 命令。
2. StateMachine 判断 clear_fault 是否处于有效状态。
3. FaultManager 判断当前故障条件是否已经消失。
4. SuperCapApp 在 clear_fault 成功后调用 ResetAfterClearFault。
```

计算逻辑冻结：

```text
dg_base = vout / vin

dg_cmd  = clamp(dg_base + dg_comp, 0.2, 5.0)
```

模式划分：

```text
dg_cmd < 0.8:
    BUCK

    d_output = 1.0

0.8 <= dg_cmd <= 1.25:

    d_input = (dg_cmd + 1.0) * 0.4
    d_output = (1.0 / dg_cmd + 1.0) * 0.4
```
