## 2. HRTIM 具体通道映射表

### 2.1 设计目的

V2.1 已经冻结：

```text
HRTIM Master Timer 100 kHz 作为统一控制时基
Master Compare Event 触发 ADC injected conversion
Charge Timer 100 kHz
Discharge Timer A/B 300 kHz
```

实际写代码前，需要把每一个功率桥臂映射到具体 HRTIM Timer、PWM 输出 IO 和 GPIO 引脚。

### 2.2 HRTIM 映射冻结表

当前硬件使用半桥驱动芯片。MCU 不直接输出高低侧互补 PWM，而是单个 PWM 信号驱动一个半桥输入，低侧互补信号与死区由半桥驱动芯片内部完成。

因此软件侧不需要配置 MCU HRTIM DeadTime 单元。

| 功能 | HRTIM Timer | PWM 输出 IO | 频率 | 相位 | 用途 | 状态 |
|---|---|---|---:|---:|---|---|
| Master 控制时基 | Master | 无 PWM 输出 | 100 kHz | 0° | ADC 触发、同步其他 Timer | 冻结 |
| Charge 输入桥臂 PWM | Timer D | PB14 | 100 kHz | 由 FSBB 调制策略决定 | 充电 FSBB 输入桥臂 | 冻结 |
| Charge 输出桥臂 PWM | Timer D | PB15 | 100 kHz | 由 FSBB 调制策略决定 | 充电 FSBB 输出桥臂 | 冻结 |
| Discharge Phase A 输入桥臂 PWM | Timer A | PA8 | 300 kHz | 0° | 放电 A 相输入桥臂 | 冻结 |
| Discharge Phase A 输出桥臂 PWM | Timer A | PA9 | 300 kHz | 0° | 放电 A 相输出桥臂 | 冻结 |
| Discharge Phase B 输入桥臂 PWM | Timer C | PB12 | 300 kHz | 180° | 放电 B 相输入桥臂 | 冻结 |
| Discharge Phase B 输出桥臂 PWM | Timer C | PB13 | 300 kHz | 180° | 放电 B 相输出桥臂 | 冻结 |

### 2.3 HRTIM 设计要求

```text
1. Master Timer 始终运行，不因 DISABLED / Fault 停止计数。
2. DISABLED / Fault 只关闭 PWM 输出，不停止 Master ADC 触发。
3. Charge Timer 和 Discharge Timer 必须由 Master 同步启动。
4. 放电 Phase A / Phase B 必须保持固定 180° 相位差。
5. MCU 单个 PWM 输出驱动一个半桥输入。
6. 半桥高低侧互补驱动和死区由半桥驱动芯片完成。
7. 软件不需要配置 HRTIM DeadTime 单元。
8. 所有 PWM Compare 更新使用 preload / shadow register。
```

### 2.4 仍需后续复核的信息

| 信息 | 来源 | 状态 |
|---|---|---|
| 每个 PWM 引脚可用的 HRTIM 输出复用功能 | CubeMX / STM32G474 AF 表 | 待 CubeMX 复核 |
| CubeMX 中 Timer A / C / D 配置是否与本文档一致 | CubeMX 工程 | 待实现时复核 |
| HRTIM Fault 输入通道与极性 | 原理图 / 调试 | 本阶段暂不考虑 |

## 3. ADC 通道映射表

### 3.1 设计目的

V2.1 已冻结：

```text
HRTIM Master Compare Event 触发 ADC injected conversion
电流环在 ADC injected conversion complete ISR 中运行
电流环频率 100 kHz
```

因此需要明确哪些信号进入 injected group，哪些信号进入 regular/DMA group。

### 3.2 快速 injected group 映射冻结表

快速 injected group 用于 100 kHz 电流环和快速过流检测。

| 信号 | ADC | Channel | Group | Rank | 频率 | 用途 | 状态 |
|---|---|---|---|---:|---:|---|---|
| I_charge_ADC | ADC2 | IN11 | Injected | 1 | 100 kHz | 充电电流环 / 充电过流 | 冻结 |
| average_I_phase1_ADC | ADC2 | IN3 | Injected | 2 | 100 kHz | 放电 A 相电流环 / 过流 | 冻结 |
| average_I_phase2_ADC | ADC2 | IN4 | Injected | 3 | 100 kHz | 放电 B 相电流环 / 过流 | 冻结 |
| V_input | ADC1 | IN2 | Injected | 1 | 100 kHz | Dg 计算 / 充电功率换算 | 冻结 |
| V_cap | ADC1 | IN6 | Injected | 2 | 100 kHz | Dg 计算 / CAP_OV / 低压锁定 | 冻结 |
| V_chassis | ADC1 | IN4 | Injected | 3 | 100 kHz | Dg 计算 / 放电电流换算 | 冻结 |

### 3.3 慢速 regular/DMA group 映射冻结表

慢速 regular/DMA group 用于功率计算、上报、辅助保护和调试。

| 信号 | ADC | Channel | Group | Rank | 频率 | 用途 | 状态 |
|---|---|---|---|---:|---:|---|---|
| I_bat | ADC1 | IN1 | Regular/DMA | 1 | 1 kHz 或更低 | 输入功率计算 | 冻结 |
| I_chassis | ADC1 | IN3 | Regular/DMA | 2 | 1 kHz 或更低 | 底盘功率计算 | 冻结 |
| Io_phase1_ADC | ADC2 | IN9 | Regular/DMA | 1 | 1 kHz 或更低 | 放电 A 相输出电流保护 / 上报 / 调试 | 冻结 |
| Io_phase2_ADC | ADC2 | IN8 | Regular/DMA | 2 | 1 kHz 或更低 | 放电 B 相输出电流保护 / 上报 / 调试 | 冻结 |

### 3.4 ADC1 / ADC2 并行分担冻结

100 kHz 周期只有 10 us，因此 injected group 不把所有通道串在一个 ADC 上完成。

冻结为：

```text
ADC2 injected:
- I_charge_ADC
- average_I_phase1_ADC
- average_I_phase2_ADC

ADC1 injected:
- V_input
- V_cap
- V_chassis
```

ADC1 和 ADC2 由同一个 HRTIM Master Compare Event 同步触发。

### 3.5 转换时间预算要求

100 kHz 快环周期：

```text
T_loop = 10 us
```

必须在 10 us 内完成：

```text
ADC 采样
ADC 转换
ADC ISR 入口
快速量更新
过流检测
电流 PI
FSBB 调制
PWM Compare shadow 更新
```

设计要求：

```text
1. injected group 只放控制必需通道。
2. 非关键上报量放 regular/DMA。
3. ADC1 / ADC2 并行分担，降低单 ADC 转换压力。
4. 后续需要用示波器或 GPIO 翻转测量 ISR 执行时间。
```

## 4. SystemState / RunMode / FaultCode 枚举编号

### 4.1 设计目的

CAN TX 需要上报 `system_state`、`run_mode` 和 `fault_code`，因此枚举值需要固定，避免主控端解析不一致。

### 4.2 SystemState 编号

```c
typedef enum
{
    SYS_DISABLED          = 0,
    SYS_RUNNING           = 1,
    SYS_CAP_OV_RECOVER    = 2,
    SYS_FAULT_RECOVERABLE = 3,
    SYS_FAULT_LATCHED     = 4,
} SystemState_t;
```

### 4.3 RunMode 编号

```c
typedef enum
{
    RUN_MODE_CHARGE    = 0,
    RUN_MODE_DISCHARGE = 1,
} RunMode_t;
```

说明：

```text
RunMode 只在 SYS_RUNNING 下有实际控制意义。
当 system_state != SYS_RUNNING 时，run_mode 推荐保持最后一次运行方向，方便判断故障前处于充电还是放电。
```

### 4.4 FaultCode 编号

```c
typedef enum
{
    FAULT_NONE                              = 0,
    FAULT_INPUT_UV                         = 1,
    FAULT_INPUT_SEVERE_UV                  = 2,
    FAULT_INPUT_OV                         = 3,
    FAULT_CAP_OV_RECOVER                   = 4,
    FAULT_CAP_OV_LATCHED                   = 5,
    FAULT_CHARGE_OC_RECOVERABLE            = 6,
    FAULT_CHARGE_OC_LATCHED                = 7,
    FAULT_DISCHARGE_PHASE_A_OC_RECOVERABLE = 8,
    FAULT_DISCHARGE_PHASE_A_OC_LATCHED     = 9,
    FAULT_DISCHARGE_PHASE_B_OC_RECOVERABLE = 10,
    FAULT_DISCHARGE_PHASE_B_OC_LATCHED     = 11,
    FAULT_DISCHARGE_TOTAL_OC_RECOVERABLE   = 12,
    FAULT_DISCHARGE_TOTAL_OC_LATCHED       = 13,
    FAULT_HRTIM_BRAKE                      = 14,
} FaultCode_t;
```

### 4.5 FaultCode 使用规则

```text
1. 同一时刻只上报最高优先级 fault_code。
2. FAULT_LATCHED 状态下保持 fault_code，直到 clear_fault 成功。
3. CAP_OV_RECOVER 期间 fault_code = FAULT_CAP_OV_RECOVER。
4. cap_ov_count >= 3 后 fault_code = FAULT_CAP_OV_LATCHED。
5. HRTIM Brake/Fault 若后续接入，则优先级最高。
```

## 5. CAN TX Byte0 同时编码 system_state + run_mode

### 5.1 设计目的

V2.1 将系统状态拆分为：

```text
SystemState + RunMode
```

原 CAN TX Byte0 仅上报 `system_state`，无法体现当前处于充电还是放电方向。

为了不增加 CAN 帧长度，在 TX Byte0 中同时编码 `system_state` 与 `run_mode`。

### 5.2 Byte0 编码冻结

```text
Byte0 bit0~3: system_state
Byte0 bit4~7: run_mode
```

编码：

```c
uint8_t state_byte = ((uint8_t)run_mode << 4) | ((uint8_t)system_state & 0x0F);
```

解码：

```c
system_state = state_byte & 0x0F;
run_mode     = (state_byte >> 4) & 0x0F;
```

### 5.3 TX 0x302 格式冻结

| Byte | 内容 |
|---|---|
| Byte0 bit0~3 | system_state |
| Byte0 bit4~7 | run_mode |
| Byte1 | fault_code |
| Byte2 | V_cap，0.2 V/bit |
| Byte3 | power_limit，W |
| Byte4~5 | P_input，0.1 W/bit，小端 |
| Byte6~7 | P_chassis，0.1 W/bit，小端 |

### 5.4 注意事项

```text
1. 主控端解析协议需要同步修改。
2. 如果 system_state != SYS_RUNNING，run_mode 推荐表示最后一次运行模式。
3. 保留最后模式可以方便调试判断故障前处于充电还是放电。
```

## 6. PWM Compare Preload 更新时机

### 6.1 设计目的

电流环在 100 kHz ADC ISR 中计算新的 FSBB duty，并写入 PWM Compare。

如果 Compare 寄存器立即生效，可能导致当前 PWM 周期中途改变比较值，引起毛刺、异常窄脉冲或上下管时序异常。

因此需要固定 PWM 更新策略。

### 6.2 设计结论

V2.1 PWM Compare 更新采用：

```text
Preload / Shadow Register 机制
```

要求：

```text
1. ADC ISR 中只写入 Compare shadow register。
2. Compare 新值在下一个 PWM Update Event 统一生效。
3. 不允许在当前 PWM 周期中途立即生效。
4. Fault 状态下的 PWM 关闭不等待 preload 更新事件。
```

### 6.3 充电 PWM 更新

充电 PWM：

```text
频率 = 100 kHz
电流环 = 100 kHz
```

设计：

```text
ADC ISR 计算本周期控制量
写入 Charge Timer Compare shadow
下一个 Charge Timer Update Event 生效
```

### 6.4 放电 PWM 更新

放电 PWM：

```text
频率 = 300 kHz
电流环 = 100 kHz
```

设计：

```text
每 3 个放电 PWM 周期执行一次电流环
ADC ISR 写入 Discharge Timer A/B Compare shadow
下一个可用的 Discharge Timer Update Event 生效
新占空比保持 3 个 PWM 周期左右，直到下一次 100 kHz 电流环更新
```

### 6.5 软件接口建议

```c
void PwmDriver_SetChargeDuty(const FsbbDuty_t *duty)
{
    // write charge compare shadow registers
}

void PwmDriver_SetDischargeDutyA(const FsbbDuty_t *duty)
{
    // write discharge phase A compare shadow registers
}

void PwmDriver_SetDischargeDutyB(const FsbbDuty_t *duty)
{
    // write discharge phase B compare shadow registers
}

void PwmDriver_AllOff(void)
{
    // immediate output disable or force output low
}
```

## 8. 结论

本文档中的工程细节属于 V2.1 软件设计说明书的工程落地补充。

当前已经冻结：

```text
1. HRTIM Timer 与主要 PWM IO 映射。
2. 半桥芯片生成互补驱动和死区，MCU 不配置 DeadTime。
3. 单个 PWM 信号驱动一个半桥输入。
4. Charge 输入/输出桥臂相位由 FSBB 调制策略决定。
5. Discharge Phase A / Phase B 固定 180° 相位差。
6. ADC2 injected 负责电流采样。
7. ADC1 injected 负责电压采样。
8. SystemState / RunMode / FaultCode 枚举编号。
9. CAN TX Byte0 同时编码 system_state + run_mode。
10. PWM Compare 使用 preload / shadow 更新。
```

当前不阻塞代码生成的事项：

```text
1. HRTIM Fault 输入通道与极性。
2. ADC ISR 执行时间实测。
3. ADC 采样点位置微调。
```
