# RM SuperCap Controller V2.1 待补充工程细节设计

## 1. 文档目的

本文档用于记录 V2.1 软件设计说明书中尚未完全落地的 5 个工程细节。

这些内容不改变 V2.1 已冻结的软件架构，但会直接影响后续代码实现、CubeMX/HRTIM 配置、ADC 配置、CAN 协议编码以及调试验证。

需要补充的 5 个细节为：

1. HRTIM 具体通道映射表。
2. ADC 通道映射表。
3. SystemState / RunMode / FaultCode 枚举编号。
4. CAN TX Byte0 同时编码 system_state + run_mode。
5. PWM Compare preload 更新时机。

### 2.3 设计要求

HRTIM 通道映射需要满足：

```text
1. Master Timer 始终运行，不因 DISABLED / Fault 停止计数。
2. DISABLED / Fault 只关闭 PWM 输出，不停止 Master ADC 触发。
3. Charge Timer 和 Discharge Timer 必须由 Master 同步启动。
4. 放电 Phase A / Phase B 必须保持固定 180° 相位差。
5. PWM 输出必须支持互补输出和 50 ns 死区。
6. 所有 PWM Compare 更新使用 preload / shadow register。
```

## 3. ADC 通道映射表

### 3.1 设计目的

V2.1 已冻结：

```text
HRTIM Master Compare Event 触发 ADC injected conversion
电流环在 ADC injected conversion complete ISR 中运行
电流环频率 100 kHz
```

因此需要明确哪些信号进入 injected group，哪些信号进入 regular/DMA group。

### 3.2 快速 injected group 建议

快速 injected group 用于 100 kHz 电流环和快速过流检测。

| 信号 | ADC | Channel | Group | Rank | 频率 | 用途 | 状态 |
|---|---|---|---|---:|---:|---|---|
| I_charge_ADC | 待填 | 待填 | Injected | 待填 | 100 kHz | 充电电流环 / 充电过流 | 待确认 |
| average_I_phase1_ADC | 待填 | 待填 | Injected | 待填 | 100 kHz | 放电 A 相电流环 / 过流 | 待确认 |
| average_I_phase2_ADC | 待填 | 待填 | Injected | 待填 | 100 kHz | 放电 B 相电流环 / 过流 | 待确认 |
| V_input | 待填 | 待填 | Injected | 待填 | 100 kHz | Dg 计算 / 充电功率换算 | 待确认 |
| V_cap | 待填 | 待填 | Injected | 待填 | 100 kHz | Dg 计算 / CAP_OV / 低压锁定 | 待确认 |
| V_chassis | 待填 | 待填 | Injected | 待填 | 100 kHz | Dg 计算 / 放电电流换算 | 待确认 |

### 3.3 慢速 regular/DMA group 建议

慢速 regular/DMA group 用于功率计算、上报、辅助保护和调试。

| 信号 | ADC | Channel | Group | Rank | 频率 | 用途 | 状态 |
|---|---|---|---|---:|---:|---|---|
| I_bat | 待填 | 待填 | Regular/DMA | 待填 | 1 kHz 或更低 | P_input 计算 | 待确认 |
| I_chassis | 待填 | 待填 | Regular/DMA | 待填 | 1 kHz 或更低 | P_chassis 计算 | 待确认 |
| Io_phase1_ADC | 待填 | 待填 | Regular/DMA | 待填 | 1 kHz 或更低 | 保护 / 上报 / 校验 | 待确认 |
| Io_phase2_ADC | 待填 | 待填 | Regular/DMA | 待填 | 1 kHz 或更低 | 保护 / 上报 / 校验 | 待确认 |
| Temperature | 待填 | 待填 | Regular/DMA | 待填 | 1 kHz 或更低 | 温度保护 / 调试 | 可选 |

### 3.4 ADC1 / ADC2 并行分担建议

100 kHz 周期只有 10 us，因此 injected group 不宜把所有通道串在一个 ADC 上完成。

建议优先考虑：

```text
ADC1 injected:
- I_charge_ADC
- average_I_phase1_ADC
- average_I_phase2_ADC

ADC2 injected:
- V_input
- V_cap
- V_chassis
```

ADC1 和 ADC2 由同一个 HRTIM Master Compare Event 同步触发。

### 3.5 转换时间预算要求

100 kHz 快环周期：

```text
T_loop = 10 us
```

必须在 10 us 内完成：

```text
ADC 采样
ADC 转换
ADC ISR 入口
快速量更新
过流检测
电流 PI
FSBB 调制
PWM Compare shadow 更新
```

因此设计要求：

```text
1. injected group 只放控制必需通道。
2. 非关键上报量放 regular/DMA。
3. 若转换时间不足，使用 ADC1 / ADC2 并行分担。
4. 后续需要用示波器或 GPIO 翻转测量 ISR 执行时间。
```

## 4. SystemState / RunMode / FaultCode 枚举编号

### 4.1 设计目的

CAN TX 需要上报 `system_state` 和 `fault_code`，因此枚举值需要固定，避免主控端解析不一致。

### 4.2 SystemState 编号

```c
typedef enum
{
    SYS_DISABLED          = 0,
    SYS_RUNNING           = 1,
    SYS_CAP_OV_RECOVER    = 2,
    SYS_FAULT_RECOVERABLE = 3,
    SYS_FAULT_LATCHED     = 4,
} SystemState_t;
```

### 4.3 RunMode 编号

```c
typedef enum
{
    RUN_MODE_CHARGE    = 0,
    RUN_MODE_DISCHARGE = 1,
} RunMode_t;
```

说明：

```text
RunMode 只在 SYS_RUNNING 下有实际控制意义。
当 system_state != SYS_RUNNING 时，run_mode 仅表示故障或禁用前的最后运行方向，或按软件实现保持默认值。
```

### 4.4 FaultCode 编号建议

```c
typedef enum
{
    FAULT_NONE                              = 0,

    FAULT_INPUT_UV                         = 1,
    FAULT_INPUT_SEVERE_UV                  = 2,
    FAULT_INPUT_OV                         = 3,

    FAULT_CAP_OV_RECOVER                   = 4,
    FAULT_CAP_OV_LATCHED                   = 5,

    FAULT_CHARGE_OC_RECOVERABLE            = 6,
    FAULT_CHARGE_OC_LATCHED                = 7,

    FAULT_DISCHARGE_PHASE_A_OC_RECOVERABLE = 8,
    FAULT_DISCHARGE_PHASE_A_OC_LATCHED     = 9,

    FAULT_DISCHARGE_PHASE_B_OC_RECOVERABLE = 10,
    FAULT_DISCHARGE_PHASE_B_OC_LATCHED     = 11,

    FAULT_DISCHARGE_TOTAL_OC_RECOVERABLE   = 12,
    FAULT_DISCHARGE_TOTAL_OC_LATCHED       = 13,

    FAULT_HRTIM_BRAKE                      = 14,
} FaultCode_t;
```

### 4.5 FaultCode 使用规则

```text
1. 同一时刻只上报最高优先级 fault_code。
2. FAULT_LATCHED 状态下保持 fault_code，直到 clear_fault 成功。
3. CAP_OV_RECOVER 期间 fault_code = FAULT_CAP_OV_RECOVER。
4. cap_ov_count >= 3 后 fault_code = FAULT_CAP_OV_LATCHED。
5. HRTIM Brake 优先级最高，可直接覆盖其他 fault_code。
```

## 5. CAN TX Byte0 同时编码 system_state + run_mode

### 5.1 设计目的

V2.1 将系统状态拆分为：

```text
SystemState + RunMode
```

原 CAN TX Byte0 仅上报 `system_state`，无法体现当前处于充电还是放电方向。

为了不增加 CAN 帧长度，建议在 TX Byte0 中同时编码 `system_state` 与 `run_mode`。

### 5.2 Byte0 编码建议

```text
Byte0 bit0~3: system_state
Byte0 bit4~7: run_mode
```

编码：

```c
uint8_t state_byte = ((uint8_t)run_mode << 4) | ((uint8_t)system_state & 0x0F);
```

解码：

```c
system_state = state_byte & 0x0F;
run_mode     = (state_byte >> 4) & 0x0F;
```

### 5.3 TX 0x302 更新后格式

| Byte | 内容 |
|---|---|
| Byte0 bit0~3 | system_state |
| Byte0 bit4~7 | run_mode |
| Byte1 | fault_code |
| Byte2 | V_cap，0.2 V/bit |
| Byte3 | power_limit，W |
| Byte4~5 | P_input，0.1 W/bit，小端 |
| Byte6~7 | P_chassis，0.1 W/bit，小端 |

### 5.4 注意事项

```text
1. 主控端解析协议需要同步修改。
2. 如果 system_state != SYS_RUNNING，run_mode 可表示最后一次运行模式。
3. 如果不希望保留最后模式，也可以在非 RUNNING 状态固定上报 RUN_MODE_CHARGE = 0。
4. 推荐保留最后模式，方便调试判断故障前处于充电还是放电。
```

## 6. PWM Compare Preload 更新时机

### 6.1 设计目的

电流环在 100 kHz ADC ISR 中计算新的 FSBB duty，并写入 PWM Compare。

如果 Compare 寄存器立即生效，可能导致当前 PWM 周期中途改变比较值，引起毛刺、异常窄脉冲或上下管时序异常。

因此需要固定 PWM 更新策略。

### 6.2 设计结论

V2.1 PWM Compare 更新采用：

```text
Preload / Shadow Register 机制
```

要求：

```text
1. ADC ISR 中只写入 Compare shadow register。
2. Compare 新值在下一个 PWM Update Event 统一生效。
3. 不允许在当前 PWM 周期中途立即生效。
4. Fault / Brake 例外，必须立即拉低 PWM 输出。
```

### 6.3 充电 PWM 更新

充电 PWM：

```text
频率 = 100 kHz
电流环 = 100 kHz
```

设计：

```text
ADC ISR 计算本周期控制量
写入 Charge Timer Compare shadow
下一个 Charge Timer Update Event 生效
```

### 6.4 放电 PWM 更新

放电 PWM：

```text
频率 = 300 kHz
电流环 = 100 kHz
```

设计：

```text
每 3 个放电 PWM 周期执行一次电流环
ADC ISR 写入 Discharge Timer A/B Compare shadow
下一个可用的 Discharge Timer Update Event 生效
新占空比保持 3 个 PWM 周期左右，直到下一次 100 kHz 电流环更新
```

### 6.5 Fault / Brake 例外处理

Fault 状态：

```text
软件 Fault：调用 PwmDriver_AllOff()
```

HRTIM Brake：

```text
硬件立即关断 PWM 输出
进入 FAULT_LATCHED
```

Fault / Brake 不等待 preload 更新事件。

### 6.6 软件接口建议

```c
void PwmDriver_SetChargeDuty(const FsbbDuty_t *duty)
{
    // write charge compare shadow registers
}

void PwmDriver_SetDischargeDutyA(const FsbbDuty_t *duty)
{
    // write discharge phase A compare shadow registers
}

void PwmDriver_SetDischargeDutyB(const FsbbDuty_t *duty)
{
    // write discharge phase B compare shadow registers
}

void PwmDriver_AllOff(void)
{
    // immediate output disable or force output low
}
```
