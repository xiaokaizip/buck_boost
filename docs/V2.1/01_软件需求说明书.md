# RM SuperCap Controller 软件需求说明书 V2.1

## 1. 文档目的

本文档定义 RM SuperCap Controller 软件 V2.1 的正式需求，作为后续软件设计、编码、调试和测试依据。

V2.1 是在 V2.0 基础上的冻结版本，重点重构内容包括：

- 状态机由单一 SystemState 重构为 `SystemState + RunMode`。
- 删除 INIT / SELF_CHECK / IDLE / SOFT_START_CHARGE / SOFT_START_DISCHARGE。
- CHARGE / DISCHARGE 不再作为 SystemState，而作为 RUNNING 下的 RunMode。
- 功率方向由功率迟滞比较器直接切换。
- 充放电切换不进入 IDLE，不主动停止 PWM，不使用软启动。
- Power PI 输出单位冻结为 W。
- FSBB 调制冻结为电压前馈 `Dg_base` 与电流环 PI 输出 `Dg_comp` 叠加。
- Fault 需求冻结。

---

## 2. 系统总体需求

系统用于 RoboMaster 超级电容控制器，硬件控制核心为 STM32G474 系列 MCU。

功率拓扑：

- 一路四开关 Buck-Boost 充电通道。
- 两路四开关 Buck-Boost 并联放电通道。
- 放电两相固定 180° 错相。

软件应实现以下功能：

- ADC 采样与物理量换算。
- 输入功率与底盘功率计算。
- Power PI 功率控制。
- 30 V 电容电压环限流。
- 充电电流环。
- 放电两相电流环。
- FSBB 三模态调制。
- HRTIM PWM 输出。
- 100% 占空比自举刷新。
- Fault 检测、恢复与锁死。
- CAN 控制与状态上报。
- 参数管理与调试数据输出接口。

## 3. 术语定义

| 名称 | 含义 |
|---|---|
| V_input / V_bat | 电池输入电压 |
| V_cap | 超级电容电压 |
| V_chassis | 底盘母线电压 |
| I_bat | 电池输入电流 |
| I_charge_ADC | 充电通道电流采样 |
| I_chassis | 底盘侧电流 |
| average_I_phase1_ADC | 放电 Phase A 平均电流反馈 |
| average_I_phase2_ADC | 放电 Phase B 平均电流反馈 |
| Io_phase1_ADC | Phase A 输出侧电流，用于保护、上报、校验 |
| Io_phase2_ADC | Phase B 输出侧电流，用于保护、上报、校验 |
| P_input | 输入功率，`V_bat * I_bat` |
| P_chassis | 底盘功率，`V_chassis * I_chassis` |
| power_limit | 主控下发的功率限制 |
| Dg_base | FSBB 电压前馈广义占空比 |
| Dg_comp | 电流环 PI 输出补偿量 |
| Dg_cmd | 最终进入 FSBB 三模态映射的广义占空比 |

## 4. 系统输入输出需求

### 4.1 CAN 输入

主控通过 CAN 下发：

- enable
- clear_fault
- power_limit

`power_limit` 参数：

| 参数 | 数值 |
|---|---:|
| 默认值 | 50 W |
| 最大值 | 120 W |
| 单位 | W |
| 超出处理 | 钳位到 120 W |

CAN enable 仅表示工作请求，不能绕过 Fault。

clear_fault 仅用于清除已经消失的锁死故障。

CAN 超时不作为 Fault。

### 4.2 ADC 输入

软件需要采样并换算：

- V_bat
- V_cap
- V_chassis
- I_bat
- I_charge_ADC
- I_chassis
- average_I_phase1_ADC
- average_I_phase2_ADC
- Io_phase1_ADC
- Io_phase2_ADC

并计算：

```text
P_input = V_bat * I_bat
P_chassis = V_chassis * I_chassis
```

## 5. 功率管理需求

V2.1 不使用裁判系统能量缓冲，不使用：

```text
ENERGY_BUFFER
energyRemain
```

功率管理仅依赖：

```text
power_limit
P_input
P_chassis
```

Power PI 的输出单位为 W。

Power PI 输出不直接作为电流，而是在不同方向下换算成充电电流参考或放电总电流参考。

---

## 6. 功率方向迟滞比较器需求

定义功率误差：

```text
P_error = power_limit - P_input
```

含义：

```text
P_error > 0：输入功率低于限制，有功率余量，可充电
P_error < 0：输入功率超过限制，需要放电补偿
```

功率方向比较器使用 ±5 W 迟滞。

切换规则：

```text
当前 RunMode = CHARGE：
    如果 P_error < -5 W
        直接切换到 DISCHARGE

当前 RunMode = DISCHARGE：
    如果 P_error > +5 W
        直接切换到 CHARGE

-5 W <= P_error <= +5 W：
    保持当前 RunMode
```

方向切换要求：

- 不进入 IDLE。
- 不主动停止 PWM。
- 不使用软启动。
- 切换时清 Power PI 积分。
- 切换时清旧方向电流环积分。
- 新方向按当前采样值和目标值直接进入闭环。

## 7. 状态机需求

V2.1 使用 `SystemState + RunMode` 架构。

### 7.1 SystemState

```text
DISABLED
RUNNING
CAP_OV_RECOVER
FAULT_RECOVERABLE
FAULT_LATCHED
```

### 7.2 RunMode

```text
RUN_MODE_CHARGE
RUN_MODE_DISCHARGE
```

CHARGE / DISCHARGE 不作为 SystemState，只作为 RUNNING 状态下的运行模式。

### 7.3 删除状态

V2.1 删除或不使用以下 V2.0 状态：

```text
INIT
SELF_CHECK
IDLE
SOFT_START_CHARGE
SOFT_START_DISCHARGE
```

### 7.4 状态优先级

```text
CAN disable
    -> DISABLED

FAULT_LATCHED
    -> FAULT_LATCHED

CAP_OV_RECOVER
    -> CAP_OV_RECOVER

FAULT_RECOVERABLE
    -> FAULT_RECOVERABLE

无故障且 CAN enable
    -> RUNNING
```

### 7.5 DISABLED

进入条件：

```text
CAN enable = 0
```

动作：

```text
所有 PWM 拉低
清 Power PI 积分
清电流环 PI 积分
清电压环 PI 积分
保持 CAN 通信
保持 ADC 采样
```

### 7.6 RUNNING

进入条件：

```text
CAN enable = 1
无 FAULT_LATCHED
无 FAULT_RECOVERABLE
不处于 CAP_OV_RECOVER
```

RUNNING 内部由 RunMode 决定充电或放电。

RunMode 由功率方向迟滞比较器决定。

### 7.7 CAP_OV_RECOVER

进入条件：

```text
V_cap > 31 V
```

动作：

```text
所有 PWM 拉低
清 Power PI 积分
清充电电流环 PI 积分
清放电电流环 PI 积分
清电压环 PI 积分
执行 cap_ov_count 事件计数
```

退出条件：

```text
V_cap <= 28 V
```

退出后：

```text
如果 CAN enable = 1，回到 RUNNING
如果 CAN enable = 0，回到 DISABLED
```

### 7.8 FAULT_RECOVERABLE

进入条件：

```text
可恢复故障触发
```

动作：

```text
所有 PWM 拉低
清 Power PI 积分
清电流环 PI 积分
清电压环 PI 积分
保持 CAN 通信
保持 ADC 采样
```

恢复条件：

```text
故障条件消失并稳定 500 ms
```

恢复后：

```text
如果 CAN enable = 1，回到 RUNNING
如果 CAN enable = 0，回到 DISABLED
```

### 7.9 FAULT_LATCHED

进入条件：

```text
锁死故障触发
```

动作：

```text
所有 PWM 拉低
清 Power PI 积分
清电流环 PI 积分
清电压环 PI 积分
保持 fault_code
保持 CAN 通信
保持 ADC 采样
```

恢复条件：

```text
当前故障条件已经消失
收到 clear_fault
```

恢复后：

```text
清 fault_code
清 cap_ov_count
清 PI 积分
如果 CAN enable = 1，回 RUNNING
如果 CAN enable = 0，回 DISABLED
```

## 8. 充电控制需求

### 8.1 充电功率参考

充电方向下，Power PI 输出充电功率参考：

```text
P_charge_ref，单位 W
```

换算为充电输入电流参考：

```text
I_charge_ref_from_power = P_charge_ref / V_input
```

### 8.2 充电输出电流估算限制

充电输出电流暂不直接采样，采用估算限制：

```text
P_charge_ref <= V_cap * 10 A
```

等效输入电流限制：

```text
I_charge_out_limit_equiv = (V_cap * 10 A) / V_input
```

### 8.3 电容电压环限流

电容电压目标：

```text
V_cap_target = 30 V
```

电压环输出单位：

```text
A
```

电压环输出作为充电电流上限：

```text
I_charge_cv_limit = VoltagePI(30 V - V_cap)
```

30 V 是控制目标，不是 Fault。

### 8.4 最终充电电流参考

最终充电电流参考：

```text
I_charge_ref = min(I_charge_ref_from_power,
                   I_charge_out_limit_equiv,
                   I_charge_cv_limit,
                   I_charge_hw_limit)
```

### 8.5 充电电流环

反馈：

```text
I_charge_ADC
```

频率：

```text
100 kHz
```

输出：

```text
Dg_comp_charge
```

## 9. 放电控制需求

### 9.1 放电功率参考

放电方向下，Power PI 输出放电功率参考：

```text
P_discharge_ref，单位 W
```

最大放电功率：

```text
P_discharge_max = 500 W
```

功率限幅：

```text
0 <= P_discharge_ref <= 500 W
```

### 9.2 放电电流参考

放电总电流参考：

```text
I_discharge_total_ref = P_discharge_ref / V_chassis
```

总电流限制：

```text
I_discharge_total_limit = 500 W / V_chassis
```

两相分配：

```text
I_phase_ref = I_discharge_total_ref / 2
```

### 9.3 放电电流环

Phase A 反馈：

```text
average_I_phase1_ADC
```

Phase B 反馈：

```text
average_I_phase2_ADC
```

电流环频率：

```text
100 kHz
```

放电 PWM 频率：

```text
300 kHz
```

电流环更新频率要求：

```text
每 3 个 300 kHz PWM 周期执行一次电流环
```

`Io_phase1_ADC` / `Io_phase2_ADC` 用于：

- 保护
- 上报
- 校验
- 调试

第一版不作为放电电流环反馈。

### 9.4 低电容电压锁定

```text
V_cap <= 8 V  -> low_cap_lock = true
V_cap >= 10 V -> low_cap_lock = false
```

当 `low_cap_lock = true` 时：

```text
禁止 DISCHARGE
强制不允许放电功率输出
```

`V_cap <= 8 V` 不是 Fault。

## 10. FSBB 调制需求

FSBB 调制采用：

```text
电压前馈 + 电流环 PI 闭环补偿叠加
```

### 10.1 基本公式

```text
Dg_base = Vout / Vin
Dg_comp = CurrentPI(I_ref - I_feedback)
Dg_cmd  = Dg_base + Dg_comp
```

### 10.2 功率方向下的 Vin / Vout

充电方向：

```text
Vin  = V_input
Vout = V_cap
Dg_base = V_cap / V_input
```

放电方向：

```text
Vin  = V_cap
Vout = V_chassis
Dg_base = V_chassis / V_cap
```

### 10.3 Dg_comp 符号定义

电流误差：

```text
I_error = I_ref - I_feedback
```

PI 输出：

```text
Dg_comp = CurrentPI(I_error)
```

要求：

```text
电流偏小 -> Dg_comp > 0 -> Dg_cmd 增大 -> 增大能量传输
电流偏大 -> Dg_comp < 0 -> Dg_cmd 减小 -> 降低能量传输
```

### 10.4 限幅

```text
Dg_comp_min = -0.5
Dg_comp_max = +0.5
Dg_cmd_min  = 0.2
Dg_cmd_max  = 5.0
```

计算顺序：

```text
Dg_comp = clamp(Dg_comp, -0.5, +0.5)
Dg_cmd  = clamp(Dg_base + Dg_comp, 0.2, 5.0)
```

### 10.5 三模态映射

```text
Dg_cmd < 0.8:
    Mode = Buck
    D_input  = 1.0
    D_output = Dg_cmd

Dg_cmd > 1.25:
    Mode = Boost
    D_input  = 1.0 / Dg_cmd
    D_output = 1.0

0.8 <= Dg_cmd <= 1.25:
    Mode = Buck-Boost
    D_input  = (Dg_cmd + 1.0) * 0.4
    D_output = (1.0 / Dg_cmd + 1.0) * 0.4
```

占空比输出范围：

```text
0% ~ 100%
```

底层 PWM Driver 负责处理 100% 占空比下的自举刷新。

## 11. PWM / HRTIM 需求

PWM 频率：

| 通道 | 频率 |
|---|---:|
| 充电 FSBB | 100 kHz |
| 放电 Phase A | 300 kHz |
| 放电 Phase B | 300 kHz |

参数：

| 参数 | 数值 |
|---|---:|
| 死区时间 | 50 ns |
| 占空比范围 | 0% ~ 100% |
| Fault 输出 | 所有 PWM 拉低 |
| 放电相位差 | 180° |

自举刷新需求：

```text
Buck：输入桥臂 100%，输入桥臂刷新
Boost：输出桥臂 100%，输出桥臂刷新
Buck-Boost：两个桥臂均参与 PWM，不额外刷新
```

默认刷新参数：

```text
每 10 个 PWM 周期刷新一次
刷新宽度 1 个 PWM 周期
```

刷新参数应通过宏定义或配置结构体管理。

## 12. ADC 参数需求

ADC 参数：

| 参数 | 数值 |
|---|---:|
| ADC 参考电压 | 3.0 V |
| ADC 位数 | 12 bit |
| 电流零点 | 1.65 V |
| INA240A1 增益 | 20 V/V |
| 电压分压 | 9k:1k，比例 10 |

电压换算：

```text
V_adc = adc_raw * 3.0 / 4095
V_real = V_adc * 10
```

电流换算：

```text
I = abs((V_adc - 1.65) / (Rshunt * 20))
```

采样电阻：

| 信号 | Rshunt |
|---|---:|
| I_bat | 5 mΩ |
| I_charge | 5 mΩ |
| I_chassis | 2 mΩ |
| I_phase_a | 2 mΩ |
| I_phase_b | 2 mΩ |

`average_I_phase1_ADC` / `average_I_phase2_ADC` 未经过二级运放增益，换算方式与相电流一致。

电流方向第一版使用绝对值，实际方向在样机调试阶段校准。

## 13. Fault 管理需求

### 13.1 Fault 状态

```text
FAULT_NONE
FAULT_RECOVERABLE
CAP_OV_RECOVER
FAULT_LATCHED
```

### 13.2 可恢复故障

输入欠压：

```text
V_input < 22 V
```

恢复条件：

```text
V_input > 23 V 且持续 500 ms
```

轻度过流：

```text
实际电流 > 动态限值 * 110%
持续 10 ms
```

动作：

```text
进入 FAULT_RECOVERABLE
所有 PWM 拉低
清 Power PI 积分
清电流环 PI 积分
清电压环 PI 积分
```

### 13.3 锁死故障

锁死故障包括：

```text
V_input < 20 V
V_input > 28 V
严重过流
HRTIM Brake
cap_ov_count >= 3
```

严重过流：

```text
实际电流 > 动态限值 * 120%
持续 2 ms
```

动作：

```text
进入 FAULT_LATCHED
所有 PWM 拉低
清 Power PI 积分
清电流环 PI 积分
清电压环 PI 积分
保持 fault_code
等待 clear_fault
```

HRTIM Brake 触发后直接进入 FAULT_LATCHED，不经过软件 110% / 120% 延时判断。

### 13.4 动态过流限值

充电过流检测对象：

```text
I_charge_ADC
```

充电动态限值：

```text
I_charge_limit = P_charge_limit / V_input
```

放电过流检测对象：

```text
average_I_phase1_ADC
average_I_phase2_ADC
Io_phase1_ADC
Io_phase2_ADC
```

放电动态限值：

```text
I_discharge_total_limit = 500 W / V_chassis
I_phase_limit = I_discharge_total_limit / 2
```

### 13.5 CAP_OV_RECOVER

触发条件：

```text
V_cap > 31 V
```

退出条件：

```text
V_cap <= 28 V
```

CAP_OV 计数规则：

```text
一次过压事件只累计一次 cap_ov_count
CAP_OV_RECOVER 期间不重复计数
V_cap <= 28 V 后本次过压事件结束
下一次 V_cap > 31 V 才允许再次计数
```

若：

```text
cap_ov_count >= 3
```

则进入 FAULT_LATCHED。

### 13.6 clear_fault

clear_fault 规则：

```text
只对 FAULT_LATCHED 有效
如果当前故障条件仍存在，则 clear_fault 无效
如果当前故障条件已经消失，则允许清除锁死故障
```

清除内容：

```text
fault_code
cap_ov_count
Power PI 积分
电流环 PI 积分
电压环 PI 积分
```

## 14. CAN 协议需求

### 14.1 RX 帧

主控到超级电容：

```text
CAN ID: 0x301
DLC: 8
```

| Byte | 内容 |
|---|---|
| Byte0 bit0 | enable |

| Byte1 | power_limit，单位 W |


| Byte | 内容 |
|---|---|
| Byte0 | system_state |
| Byte1 | fault_code |
| Byte2 | V_cap，0.2 V/bit |
| Byte3 | power_limit，W |
| Byte4~5 | P_input，0.1 W/bit，小端 |
| Byte6~7 | P_chassis，0.1 W/bit，小端 |

CAN TX 周期暂定：

```text
10 ms
```
