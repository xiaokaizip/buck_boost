# RM SuperCap Controller 软件设计说明书 V2.1

## 1. 文档目的

本文档基于《RM SuperCap Controller 软件需求说明书 V2.1》，描述 RM SuperCap Controller V2.1 的软件架构、模块划分、控制链路、状态机、Fault 处理、ADC 触发、电流环运行位置、FSBB 调制、PWM/HRTIM、CAN 协议和代码组织方案。

本文档用于指导后续代码实现、调试、测试和维护。

---

## 2. V2.1 设计冻结摘要

V2.1 已冻结以下设计决策：

1. 状态机采用 `SystemState + RunMode`。
2. 删除 INIT / SELF_CHECK / IDLE / SOFT_START。
3. CHARGE / DISCHARGE 只作为 RUNNING 下的 RunMode。
4. 充放电通过功率迟滞比较器直接切换。
5. RunMode 切换时不进入 IDLE，不软启动。
6. RunMode 切换时旧方向 PWM 立即拉低，新方向直接闭环输出。
7. Power PI 使用两个实例：`ChargePowerPI` 与 `DischargePowerPI`。
8. 放电第一版不做额外均流环，两相各自跟踪相同 `I_phase_ref`。
9. 统一使用 `SuperCapContext_t` 保存系统上下文。
10. 严重过流 2 ms 检测放到 100 kHz 快环。
11. 电流环不放在 FreeRTOS Task 中，而放在 ADC 转换完成中断快环。
12. 使用 HRTIM Master Timer 产生 100 kHz 控制时基。
13. HRTIM Master Compare 事件统一触发 ADC injected conversion。
14. HRTIM Master Timer 同步启动充电 100 kHz Timer 与放电 300 kHz Timer。
15. ADC 触发源不随 CHARGE / DISCHARGE 切换而变化。
16. FSBB 调制采用 `Dg_cmd = Dg_base + Dg_comp`。

## 3. 软件总体架构

软件采用分层架构：

```text
Application Layer
├── supercap_app
├── state_machine
└── mode_manager

Control Layer
├── power_manager
├── charge_manager
├── discharge_manager
├── voltage_manager
├── pi_controller
└── fsbb_modulator

Protection / Communication Layer
├── fault_manager
├── can_protocol
└── debug_protocol

Driver Layer
├── adc_manager
├── pwm_driver
├── hrtim_pwm
├── can_driver
└── gpio_driver

Config Layer
└── supercap_param
```

### 3.1 分层职责

| 层级 | 职责 |
|---|---|
| Application Layer | 系统流程、状态机、运行模式调度 |
| Control Layer | Power PI、电压环、电流环、FSBB 调制 |
| Protection / Communication Layer | Fault 检测、CAN 通信、调试输出 |
| Driver Layer | ADC、PWM/HRTIM、CAN、GPIO 等硬件操作 |
| Config Layer | 集中管理参数、阈值、宏定义 |

## 5. 统一上下文设计

V2.1 使用统一上下文结构体，避免模块间散乱使用全局变量。

```c
typedef struct
{
    SuperCapCmd_t cmd;
    SuperCapMeas_t meas;
    SuperCapStatus_t status;

    PowerManager_t power;
    ChargeManager_t charge;
    DischargeManager_t discharge;
    FaultManager_t fault;
} SuperCapContext_t;
```

设计要求：

- 高频 ISR 中只访问必要字段。
- 慢环更新状态、功率参考、故障状态。
- CAN 与 Debug 从 Context 中读取状态并上报。
- 不允许多个模块重复维护同一物理量。

## 7. HRTIM 与 ADC 触发设计

### 7.1 设计结论

V2.1 不使用两个高级定时器分别触发 ADC。

系统统一使用：

```text
HRTIM Master Timer 100 kHz 控制时基
```

由 HRTIM Master Compare 事件触发 ADC injected conversion。

ADC injected conversion 完成后进入 ADC 转换完成中断，在该中断中运行 100 kHz 电流环。

### 7.2 定时器职责

| HRTIM 单元 | 频率 | 职责 |
|---|---:|---|
| Master Timer | 100 kHz | 控制时基、ADC 触发、同步其他 Timer |
| Charge Timer | 100 kHz | 充电 FSBB PWM 输出 |
| Discharge Timer A | 300 kHz | 放电 Phase A FSBB PWM 输出 |
| Discharge Timer B | 300 kHz | 放电 Phase B FSBB PWM 输出，和 Phase A 180° 错相 |

### 7.3 同步关系

HRTIM Master Timer、Charge Timer、Discharge Timer A/B 必须同步启动。

要求：

```text
Master Timer 100 kHz 周期 = 10 us
Discharge PWM 300 kHz 周期 = 3.333 us
1 个 Master 周期对应 3 个 Discharge PWM 周期
```

这样可以保证：

```text
放电电流环每 3 个 300 kHz PWM 周期执行一次
ADC 采样点与放电 PWM 具有固定相位关系
```

### 7.4 ADC 触发源

ADC 触发源固定为：

```text
HRTIM Master Compare Event
```

ADC 触发源不随 RunMode 切换而变化。

RunMode 切换时：

```text
ADC 继续由 Master Timer 触发
CurrentLoop_ISR 继续 100 kHz 运行
ISR 内根据 RunMode 选择执行 Charge 或 Discharge 控制
```

### 7.5 采样点位置

第一版建议：

```text
Master 100 kHz 周期中点附近触发 ADC
```

即：

```text
10 us 周期内约 5 us 处触发
```

后续根据示波器观察的采样噪声调整 Master Compare 位置。

### 7.6 ADC 通道分组

快速 injected group 建议包含高频控制必需通道：

```text
I_charge
average_I_phase1
average_I_phase2
V_input
V_cap
V_chassis
```

慢速 regular/DMA group 可包含：

```text
I_bat
I_chassis
Io_phase1
Io_phase2
温度
其他调试量
```

实际通道分配需结合 ADC1/ADC2 资源和硬件引脚最终确定。

## 8. 控制环调度设计

### 8.1 控制频率

| 控制项 | 频率 | 运行位置 |
|---|---:|---|
| 充电电流环 | 100 kHz | ADC injected complete ISR |
| 放电电流环 | 100 kHz | ADC injected complete ISR |
| 严重过流检测 | 100 kHz | ADC injected complete ISR |
| 轻度过流检测 | 100 kHz 计数，慢环处理状态 | ADC ISR + FaultManager |
| Power PI | 1 kHz | SlowLoop / RTOS Task |
| Voltage PI | 1 kHz | SlowLoop / RTOS Task |
| StateMachine | 1 kHz | SlowLoop / RTOS Task |
| Fault 状态处理 | 1 kHz | SlowLoop / RTOS Task |
| CAN TX | 10 ms | RTOS Task / Timer |

### 8.2 快环执行内容

快环只允许执行短路径控制逻辑。

```c
void CurrentLoop_ISR(void)
{
    AdcManager_UpdateFastSignals(&g_ctx.meas);

    FaultManager_FastOverCurrentCheck(&g_ctx);

    if (g_ctx.status.system_state != SYS_RUNNING)
    {
        PwmDriver_AllOff();
        return;
    }

    if (g_ctx.status.run_mode == RUN_MODE_CHARGE)
    {
        PwmDriver_DisableDischarge();

        ChargeManager_UpdateCurrentLoop100kHz(&g_ctx);

        FsbbDuty_t duty;
        FsbbModulator_CalcCharge(g_ctx.meas.v_input,
                                 g_ctx.meas.v_cap,
                                 g_ctx.charge.dg_comp,
                                 &duty);

        PwmDriver_SetChargeDuty(&duty);
    }
    else
    {
        PwmDriver_DisableCharge();

        DischargeManager_UpdateCurrentLoop100kHz(&g_ctx);

        FsbbDuty_t duty_a;
        FsbbDuty_t duty_b;

        FsbbModulator_CalcDischarge(g_ctx.meas.v_cap,
                                    g_ctx.meas.v_chassis,
                                    g_ctx.discharge.dg_comp_a,
                                    &duty_a);

        FsbbModulator_CalcDischarge(g_ctx.meas.v_cap,
                                    g_ctx.meas.v_chassis,
                                    g_ctx.discharge.dg_comp_b,
                                    &duty_b);

        PwmDriver_SetDischargeDutyA(&duty_a);
        PwmDriver_SetDischargeDutyB(&duty_b);
    }
}
```

### 8.3 快环禁止事项

快环内禁止：

- printf。
- CAN 打包或发送。
- Debug 数据格式化。
- Flash 写入。
- 复杂状态机跳转。
- 动态内存分配。
- 长时间循环。

## 9. 慢环设计

慢环建议 1 kHz 运行。

```c
void SuperCapApp_SlowLoop1kHz(void)
{
    AdcManager_UpdateSlowSignals(&g_ctx.meas);

    FaultManager_SlowUpdate(&g_ctx);

    StateMachine_Update(&g_ctx);

    if (g_ctx.status.system_state == SYS_RUNNING)
    {
        PowerManager_Update1kHz(&g_ctx);
        VoltageManager_Update1kHz(&g_ctx);
    }
    else
    {
        PowerManager_Reset(&g_ctx.power);
        ChargeManager_Reset(&g_ctx.charge);
        DischargeManager_Reset(&g_ctx.discharge);
    }
}
```

执行顺序冻结为：

```text
FaultManager_SlowUpdate()
StateMachine_Update()
PowerManager_Update1kHz()
VoltageManager_Update1kHz()
```

原因：状态机需要基于最新 Fault 标志决定系统状态。

## 10. PowerManager 设计

### 10.1 两个 Power PI 实例

V2.1 使用两个 Power PI 实例：

```text
ChargePowerPI
DischargePowerPI
```

原因：

- 避免功率误差符号混乱。
- 充电和放电可独立限幅。
- 切换 RunMode 时可以清旧方向积分。
- 后续调参互不影响。

### 10.2 充电功率 PI

```text
P_charge_error = power_limit - P_input
P_charge_ref = ChargePowerPI(P_charge_error)
P_charge_ref = clamp(P_charge_ref, 0, P_charge_max)
```

### 10.3 放电功率 PI

```text
P_discharge_error = P_input - power_limit
P_discharge_ref = DischargePowerPI(P_discharge_error)
P_discharge_ref = clamp(P_discharge_ref, 0, 500 W)
```

### 10.4 功率方向比较器

```text
P_error = power_limit - P_input
```

```text
当前 CHARGE 且 P_error < -5 W：切换到 DISCHARGE
当前 DISCHARGE 且 P_error > +5 W：切换到 CHARGE
-5 W <= P_error <= +5 W：保持当前 RunMode
```

切换动作：

```text
清 Power PI 积分
清旧方向电流环积分
旧方向 PWM 立即拉低
新方向直接闭环输出
```

## 11. ChargeManager 设计

### 11.1 充电控制链路

```text
ChargePowerPI 输出 P_charge_ref
    ↓
P_charge_ref <= V_cap * 10 A
    ↓
I_charge_ref_from_power = P_charge_ref / V_input
    ↓
Voltage PI 输出 I_charge_cv_limit
    ↓
I_charge_ref = min(I_charge_ref_from_power,
                   I_charge_out_limit_equiv,
                   I_charge_cv_limit,
                   I_charge_hw_limit)
    ↓
I_error = I_charge_ref - I_charge_ADC
    ↓
Charge Current PI
    ↓
Dg_comp_charge
```

### 11.2 充电环运行位置

| 环路 | 频率 | 位置 |
|---|---:|---|
| ChargePowerPI | 1 kHz | SlowLoop |
| VoltagePI | 1 kHz | SlowLoop |
| ChargeCurrentPI | 100 kHz | ADC ISR |

## 12. DischargeManager 设计

### 12.1 放电控制链路

```text
DischargePowerPI 输出 P_discharge_ref
    ↓
P_discharge_ref = clamp(P_discharge_ref, 0, 500 W)
    ↓
I_discharge_total_ref = P_discharge_ref / V_chassis
    ↓
I_phase_ref = I_discharge_total_ref / 2
    ↓
Phase A Current PI
Phase B Current PI
    ↓
Dg_comp_A / Dg_comp_B
```

### 12.2 两相均流策略

第一版不增加额外主动均流环。

设计为：

```text
Phase A 电流环跟踪 I_phase_ref
Phase B 电流环跟踪 I_phase_ref
```

若后续样机发现两相电流偏差较大，再增加 `current_balance_loop`。

### 12.3 放电环运行位置

| 环路 | 频率 | 位置 |
|---|---:|---|
| DischargePowerPI | 1 kHz | SlowLoop |
| Phase A CurrentPI | 100 kHz | ADC ISR |
| Phase B CurrentPI | 100 kHz | ADC ISR |

## 13. FSBB Modulator 设计

### 13.1 基本公式

```text
Dg_base = Vout / Vin
Dg_comp = CurrentPI(I_ref - I_feedback)
Dg_cmd  = Dg_base + Dg_comp
```

限幅：

```text
Dg_comp = clamp(Dg_comp, -0.5, +0.5)
Dg_cmd  = clamp(Dg_base + Dg_comp, 0.2, 5.0)
```

### 13.2 方向定义

充电：

```text
Vin = V_input
Vout = V_cap
```

放电：

```text
Vin = V_cap
Vout = V_chassis
```

### 13.3 三模态映射

```c
if (Dg_cmd < 0.8f)
{
    mode = FSBB_MODE_BUCK;
    D_input  = 1.0f;
    D_output = Dg_cmd;
}
else if (Dg_cmd > 1.25f)
{
    mode = FSBB_MODE_BOOST;
    D_input  = 1.0f / Dg_cmd;
    D_output = 1.0f;
}
else
{
    mode = FSBB_MODE_BUCK_BOOST;
    D_input  = (Dg_cmd + 1.0f) * 0.4f;
    D_output = (1.0f / Dg_cmd + 1.0f) * 0.4f;
}
```

## 14. PWM Driver 设计

### 14.1 输出原则

```text
RUN_MODE_CHARGE：
    允许充电 PWM 输出
    放电 Phase A/B PWM 拉低

RUN_MODE_DISCHARGE：
    允许放电 Phase A/B PWM 输出
    充电 PWM 拉低

非 RUNNING 状态：
    所有 PWM 拉低
```

### 14.2 自举刷新

```text
Buck：输入桥臂 100%，输入桥臂刷新
Boost：输出桥臂 100%，输出桥臂刷新
Buck-Boost：不额外刷新
```

默认：

```text
每 10 个 PWM 周期刷新一次
刷新宽度 1 个 PWM 周期
```

### 14.3 主要接口

```c
void PwmDriver_Init(void);
void PwmDriver_AllOff(void);
void PwmDriver_DisableCharge(void);
void PwmDriver_DisableDischarge(void);
void PwmDriver_SetChargeDuty(const FsbbDuty_t *duty);
void PwmDriver_SetDischargeDutyA(const FsbbDuty_t *duty);
void PwmDriver_SetDischargeDutyB(const FsbbDuty_t *duty);
void PwmDriver_BootstrapRefreshUpdate(void);
```

## 15. FaultManager 设计

### 15.1 Fault 检测分层

Fault 检测分为快环检测和慢环状态处理。

快环检测：

```text
严重过流 120%，2 ms
轻度过流计数
```

慢环处理：

```text
输入欠压 / 过压
CAP_OV 状态
FAULT_RECOVERABLE 状态切换
FAULT_LATCHED 状态切换
clear_fault
```

### 15.2 过流计数

100 kHz 快环计数：

```text
2 ms = 200 counts
10 ms = 1000 counts
```

严重过流：

```text
actual_current > dynamic_limit * 120%
持续 200 counts
-> 置位 oc_latched_flag
```

轻度过流：

```text
actual_current > dynamic_limit * 110%
持续 1000 counts
-> 置位 oc_recoverable_flag
```

### 15.3 CAP_OV 事件计数

```c
if ((v_cap > VCAP_OV_ENTER_V) && !cap_ov_event_latched)
{
    cap_ov_event_latched = true;
    cap_ov_count++;
}

if ((state == SYS_CAP_OV_RECOVER) && (v_cap <= VCAP_OV_EXIT_V))
{
    cap_ov_event_latched = false;
}
```

CAP_OV_RECOVER 期间不重复计数。

### 15.4 clear_fault

```text
clear_fault 只对 FAULT_LATCHED 有效
故障条件仍存在时无效
故障条件消失后清 fault_code、cap_ov_count、PI 积分
```

## 16. StateMachine 设计

### 16.1 状态转移表

| 当前状态 | 条件 | 下一状态 | 动作 |
|---|---|---|---|
| 任意状态 | enable = 0 | DISABLED | PWM_AllOff，清 PI |
| DISABLED | enable = 1 且无故障 | RUNNING | 保持 PWM 关闭，等待快环输出 |
| RUNNING | V_cap > 31 V | CAP_OV_RECOVER | PWM_AllOff，CAP_OV 事件计数 |
| RUNNING | 可恢复故障 | FAULT_RECOVERABLE | PWM_AllOff，清 PI |
| RUNNING | 锁死故障 | FAULT_LATCHED | PWM_AllOff，清 PI，保持 fault_code |
| CAP_OV_RECOVER | V_cap <= 28 V 且 enable = 1 | RUNNING | 清 cap_ov_event_latched |
| CAP_OV_RECOVER | cap_ov_count >= 3 | FAULT_LATCHED | PWM_AllOff，保持 fault_code |
| FAULT_RECOVERABLE | 故障消失 500 ms 且 enable = 1 | RUNNING | 清 PI |
| FAULT_LATCHED | clear_fault 有效且 enable = 1 | RUNNING | 清 fault_code，清 cap_ov_count，清 PI |
| FAULT_LATCHED | clear_fault 有效且 enable = 0 | DISABLED | 清 fault_code，清 cap_ov_count，清 PI |

### 16.2 RunMode 转移表

| 当前 RunMode | 条件 | 下一 RunMode | 动作 |
|---|---|---|---|
| CHARGE | `P_error < -5 W` 且 `low_cap_lock = false` | DISCHARGE | 清 ChargePowerPI / ChargeCurrentPI，充电 PWM 拉低 |
| DISCHARGE | `P_error > +5 W` | CHARGE | 清 DischargePowerPI / DischargeCurrentPI，放电 PWM 拉低 |
| DISCHARGE | `low_cap_lock = true` | CHARGE | 放电 PWM 拉低，禁止放电 |
| CHARGE | `-5 W <= P_error <= +5 W` | CHARGE | 保持 |
| DISCHARGE | `-5 W <= P_error <= +5 W` | DISCHARGE | 保持 |

## 18. CANProtocol 设计

| Byte | 内容 |
|---|---|
| Byte0 bit0 | enable |
| Byte0 bit1 | clear_fault |
| Byte1 | power_limit，单位 W |
| Byte2~7 | reserved |

### 18.2 TX 0x302

| Byte | 内容 |
|---|---|
| Byte0 | system_state |
| Byte1 | fault_code |
| Byte2 | V_cap，0.2 V/bit |

### 18.3 编码要求

## 21. 设计冻结结论

V2.1 软件设计冻结为：

```text
HRTIM Master Timer 100 kHz 作为统一控制时基。
Master Compare 事件触发 ADC injected conversion。
ADC injected conversion complete ISR 中运行 100 kHz 电流环。
Charge PWM 100 kHz。
Discharge PWM 300 kHz。
放电电流环 100 kHz，每 3 个放电 PWM 周期更新一次。
Power PI 与 Voltage PI 运行在 1 kHz 慢环。
StateMachine 与 Fault 状态处理运行在 1 kHz 慢环。
严重过流检测运行在 100 kHz 快环。
RunMode 切换时旧方向 PWM 立即拉低，新方向直接闭环输出。
```
