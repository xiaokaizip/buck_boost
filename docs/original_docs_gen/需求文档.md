# 需求文档

## 1. 项目概述

本项目为基于 STM32G474RBT6 的 RoboMaster 超级电容控制器软件需求文档。

系统采用三端口结构：

- 电源输入口
- 超级电容接口
- 机器人底盘接口

电源输入口用于为系统供电，并受 `power_limit` 限制。底盘口直接连接机器人底盘。当底盘功率低于 `power_limit` 时，多余功率用于给超级电容充电；当底盘功率高于 `power_limit` 时，超级电容进入放电模式，与电源共同为底盘供电。

本项目的拓扑与参考资料中的单路双向 Buck-Boost 不同。本设计将充电和放电独立开来：

- 充电：一路四开关 Buck-Boost。
- 放电：两相并联交错四开关 Buck-Boost。

放电两相相位错开 180°，每一相具有独立电流环。

## 2. 软件总体要求

软件使用 FreeRTOS。

控制频率大于 1kHz 的逻辑应放在中断中运行；小于等于 1kHz 的逻辑应放在 FreeRTOS task 中运行。

中断中不得出现：

- 阻塞函数
- 延时函数
- 打印函数
- 可能等待互斥锁/队列的函数
- 动态内存分配

代码要求：

- 模块化分文件编写。
- 命名格式统一。
- 变量名不易混淆。
- 控制逻辑简洁易懂。
- 关键控制和保护逻辑需要注释。
- 便于后续修改和调试。

## 3. 三端口功率关系

### 3.1 电源输入口

电源输入口提供系统输入功率。

输入功率定义为：

```text
P_input = V_bat * I_bat
```

电源输入功率受 `power_limit` 限制。

### 3.2 超级电容接口

超级电容接口用于超级电容充电和放电。

充电时，能量从电源输入口流向超级电容。

放电时，能量从超级电容流向底盘口。

### 3.3 底盘接口

底盘接口连接机器人底盘。

底盘功率定义为：

```text
P_chassis = V_chassis * I_chassis
```

当：

```text
P_chassis < power_limit
```

系统可使用剩余功率为超级电容充电。

当：

```text
P_chassis > power_limit
```

系统应进入放电模式，由超级电容补足超出 `power_limit` 的部分。

## 4. 拓扑需求

### 4.1 充电拓扑

充电通道为一路四开关 Buck-Boost。

其工作对象为：

```text
输入端：电源输入口
输出端：超级电容口
```

该通道应支持：

- Buck 模式
- Boost 模式
- Buck-Boost 模式

### 4.2 放电拓扑

放电通道由两路四开关 Buck-Boost 并联组成。

其工作对象为：

```text
输入端：超级电容口
输出端：底盘口
```

两相要求：

- 相位错开 180°。
- 每相独立电流环。
- 每相参考电流为总放电电流的一半。
- 前期可依靠两相独立电流环实现自然均流。

### 4.3 充放电互斥

充电和放电尽量不能同时进行。

如果因为切换时序导致短时间重叠，需要限制同时运行时间，并确保不会出现能量环流。

当前建议：

- 正常状态下充电和放电互斥。
- 切换时先关闭当前模式，再进入另一模式软启动。
- 后续如需要无缝切换，再增加过渡状态。

## 5. FSBB 模式切换需求

每一路 FSBB 均需要支持三种模式：

- Buck
- Buck-Boost
- Boost

模式切换应参考资料中的广义占空比思想。

建议采用统一调制模块：

```text
fsbb_modulator
```

上层控制器不直接关心具体桥臂占空比，只输出统一控制量，具体模式选择和桥臂 PWM 由 `fsbb_modulator` 完成。

## 6. 自举刷新需求

由于硬件使用自举高边驱动，高边 MOS 不能无限期常开。

当某一桥臂上管需要长时间导通时，需要周期性短暂打开下管，为自举电容充电。

要求：

- 自举刷新周期可配置。
- 自举刷新脉宽可配置。
- 刷新期间避免 ADC 采样污染。
- 刷新动作由底层 PWM/FSBB 调制模块处理。
- 上层功率环和电流环不应直接处理自举刷新细节。

## 7. 功率环需求

功率环用于控制电源输入功率不超过功率限制。

控制目标：

```text
P_input <= power_limit
```

功率环输入：

```text
P_input
power_limit
```

功率环输出用于判断当前应充电还是放电，并决定充放电功率或电流参考。

功率环方案需要参考资料中的实现方式，并在后续设计中进一步确认。

## 8. 充电控制需求

充电需要考虑三个因素：

- 输入充电功率
- 电容电压环
- 输入电流环

充电控制需要处理功率环、电压环和电流环之间的关系。

可选结构包括：

- 串联结构
- 并联限幅结构
- 串并联结构

当前建议采用：

```text
功率限制 -> 电流参考
电压环 -> 电流限幅
硬件限制 -> 电流限幅
最终电流参考 -> 输入电流环
```

即：

```text
I_charge_ref = min(I_power_limit, I_cv_limit, I_hw_limit, I_slew_limit)
```

其中：

- `I_power_limit` 来自功率限制。
- `I_cv_limit` 来自电容电压环。
- `I_hw_limit` 来自硬件安全限制。
- `I_slew_limit` 来自软启动和斜率限制。

## 9. 放电控制需求

放电模式下，控制目标是让输入功率不超过 `power_limit`。

放电功率由功率环输出。

总放电电流可由放电功率除以底盘电压得到：

```text
I_discharge_total_ref = P_discharge_ref / V_chassis
```

每相电流参考：

```text
I_phase_ref = I_discharge_total_ref / 2
```

每一相具有独立电流环。

### 9.1 放电电流采样选择

硬件存在：

- 电感平均电流采样
- 输出电流采样

当前更偏向使用电感平均电流采样作为电流环反馈。

风险点：

- 电感平均电流与输出电流在不同模式下关系不同。
- Buck/Boost/Buck-Boost 模态切换时，采样含义可能变化。
- 两相并联时，采样比例误差会导致均流偏差。
- 采样带宽和滤波延时会影响电流环稳定性。

备选方案：

- 若电感平均电流采样效果不好，则改用输出电流采样。
- 输出电流采样可用于保护、功率估算和上报。

## 10. CAN 通信需求

需要根据参考资料中的 CAN 协议完成 CAN 通信。

主控下发到超级电容控制器的 CAN 包中需要增加 `power_limit`。

`power_limit` 不超过 255，因此一个 byte 足够。

CAN 需要实现：

- 接收主控控制命令。
- 接收功率限制。
- 上报电容状态。
- 上报功率、电压、电流信息。
- 上报故障状态。

## 11. 串口通信需求

需要查找参考资料中与裁判系统相关的串口通讯代码。

如果没有找到，则当前版本不实现裁判系统串口通信。

当前版本不依赖裁判系统缓存能量信息。

## 12. 采样需求

三个端口均需要电压采样：

- 电源输入端电压
- 超级电容端电压
- 底盘端电压

电流采样包括：

- 电源端口电流
- 充电输入端口电流
- 每一相放电输出电流
- 每一相放电电感平均电流

采样数据用于：

- 功率计算
- 电流环反馈
- 电压环反馈
- 故障保护
- CAN 上报
- 调试输出

## 13. 保护需求

硬件增加比较器保护。

电流采样接入 STM32G474 比较器。

当比较器触发阈值时，HRTIM 需要进入 brake 状态，直接关闭 PWM。

软件需要处理：

- 硬件 brake 状态检测。
- Fault 状态记录。
- PWM 关闭。
- PI 积分清零。
- 故障恢复或锁死。
- 保护复位 GPIO 控制。

## 14. 调试接口需求

需要提供调试接口，用于查看：

- ADC 原始值
- 电压换算值
- 电流换算值
- P_input
- P_chassis
- power_limit
- 当前状态机状态
- 当前 Fault code
- 当前模式
- 各环路参考值
- 各环路输出值
- PWM 占空比

调试接口可使用串口或窗口工具。

## 15. 任务划分需求

建议任务划分：

### 15.1 高频中断

高于 1kHz 的控制逻辑放在中断中。

包括：

- ADC 采样完成处理
- 电流环
- PWM 更新
- 快速故障检测

### 15.2 FreeRTOS 任务

小于等于 1kHz 的逻辑放在 FreeRTOS task 中。

包括：

- 状态机任务
- 功率环任务
- 电压环任务
- CAN 处理任务
- 调试输出任务
- 慢速故障检测任务
