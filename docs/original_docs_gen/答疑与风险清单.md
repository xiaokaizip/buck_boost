# 答疑与风险清单

## 1. 当前已确认结论

### 1.1 不使用缓存功率/缓冲能量

当前版本不使用裁判系统缓存功率、缓冲能量、`energyRemain` 或 `ENERGY_BUFFER` 参与控制。RM2024 代码中的能量慢环只作为理解资料，不纳入本项目需求。

本项目功率管理只使用：

- `power_limit`
- `P_input = V_bat * I_bat`
- `P_chassis = V_chassis * I_chassis`
- `P_margin = power_limit - P_chassis`

### 1.2 功率环不直接输出 PWM

功率环直接竞争 PWM 会造成量纲混乱，也不利于调试和限流。当前推荐链路为：

```text
功率目标 -> 充/放电功率给定 -> 电流给定 -> 电流内环 -> 广义占空比 -> PWM
```

这样可以让功率环、电压环、安全限流都统一到电流给定或电流限值，再由最内层电流环控制功率级。

### 1.3 充电侧采用外环竞争电流给定

充电控制推荐：

```text
I_charge_ref = min(I_power_limit, I_cv_limit, I_hw_limit, I_slew_limit)
```

其中：

- `I_power_limit` 来自功率余量。
- `I_cv_limit` 来自电容电压限压环。
- `I_hw_limit` 来自硬件安全限制。
- `I_slew_limit` 用于软启动和目标斜率限制。

### 1.4 放电侧采用功率环 + 电流环

放电控制推荐：

```text
P_error = P_input - power_limit
P_error -> 功率 PI/PID -> I_discharge_ref_total
I_discharge_ref_total / 2 -> phase1/phase2 电流环
```

两相均流前期可先依赖每相独立电流环，后期再增加均流补偿。

### 1.5 充放电切换需要迟滞和最小保持时间

如果直接根据 `P_margin` 正负切换，会在功率边界附近来回跳变。需要引入：

- 充电进入死区。
- 放电进入死区。
- 状态最小保持时间。
- 目标值斜率限制。

## 2. 仍需确认的问题

### 2.1 `power_limit` 单位与来源

当前默认按 W 处理，但需最终确认：

| 问题 | 当前建议 | 状态 |
| --- | --- | --- |
| `power_limit` 单位 | W | 待最终确认 |
| `power_limit` 默认值 | 0 或保守值 | 待确认 |
| `power_limit` 失效处理 | 关闭充放电或使用安全默认值 | 待确认 |
| CAN 超时阈值 | 100ms~500ms | 待确认 |

### 2.2 输入功率 `P_input` 的定义

需要确认 `P_input` 是否只使用 `V_bat * I_bat`，以及 `I_bat` 的方向定义：

- 输入电源流入系统为正？
- 电容反灌输入是否可能？
- 采样极性是否需要软件取反？

### 2.3 底盘功率 `P_chassis` 的定义

需要确认 `I_chassis` 的方向，以及底盘端是否可能反灌。

### 2.4 充电电流控制对象

当前硬件存在 `I_charge_ADC`。需要确认它测的是：

- 充电输入电流；
- 充电电感电流；
- 电容充电电流；
- 还是某个桥臂电流。

该定义会影响电流环被控对象。

### 2.5 放电电流采样对象

功率板存在：

- `average_I_phase1_ADC`
- `average_I_phase2_ADC`
- `Io_phase1_ADC`
- `Io_phase2_ADC`

需确认控制环反馈到底使用平均电感电流还是输出电流。

当前建议：

- 电流环优先用 `average_I_phase*_ADC`。
- 输出电流用于功率估算、保护和上报。

## 3. 关键风险

### 3.1 HRTIM brake 与软件状态机耦合风险

如果硬件比较器直接触发 HRTIM brake，软件必须能够检测并处理 brake 状态，否则可能出现：

- PWM 已被硬件关断但软件仍认为正在运行。
- 故障清除顺序错误。
- PI 积分继续累积。

建议：

```text
硬件 brake -> Fault Manager 捕获 -> 关闭控制输出 -> 清积分 -> 等待复位条件
```

### 3.2 自举刷新导致采样污染

Buck 或 Boost 模式下，如果某个高边长时间导通，需要插入自举刷新脉冲。刷新期间电流波形会发生突变，可能污染 ADC 采样。

建议：

- 刷新周期和刷新脉宽可配置。
- ADC 触发点避开刷新窗口。
- 必要时丢弃刷新周期采样。

### 3.3 三模态切换不连续风险

Buck、Buck-Boost、Boost 三模态切换时，如果广义占空比映射不连续，可能造成电流突变。

建议：

- 三模态映射统一由 `fsbb_modulator` 实现。
- 上层控制环只输出统一控制量。
- 模式切换增加迟滞。
- 切换时限制占空比变化率。

### 3.4 放电两相均流风险

两相参数不一致可能导致一相电流长期偏大。

建议：

- 前期使用独立电流环自然均流。
- 后期加入均流补偿：

```text
I_balance_error = I_phase1 - I_phase2
G_phase1 -= K_balance * I_balance_error
G_phase2 += K_balance * I_balance_error
```

### 3.5 ADC 零点与比例误差风险

电流采样零点偏差会直接影响功率计算和过流保护。

建议：

- 上电无电流时进行零点标定。
- 电压/电流比例参数集中放在 `supercap_param.h`。
- 调试接口支持查看原始 ADC 和换算值。

### 3.6 CAN 失效风险

如果 CAN 掉线后继续使用旧 `power_limit`，可能违反功率限制。

建议：

- CAN 超时进入安全状态。
- 或 power_limit 降为安全默认值。
- 具体策略待确认。

## 4. 模块实现建议

### 4.1 Power Manager

职责：

- 计算 `P_input`、`P_chassis`、`P_margin`。
- 根据系统状态生成充放电功率目标。
- 执行功率环。
- 提供给 Charge/Discharge 控制器。

### 4.2 Charge Controller

职责：

- 根据功率目标、电压限流、硬件限流生成 `I_charge_ref`。
- 执行充电电流环。
- 调用 FSBB 调制器生成 PWM。

### 4.3 Discharge Controller

职责：

- 根据功率环输出生成总放电电流参考。
- 分配到两相。
- 执行两相电流环。
- 调用 FSBB 调制器生成每相 PWM。

### 4.4 Fault Manager

职责：

- 统一检测软件故障。
- 读取/处理硬件保护状态。
- 管理可恢复/锁死故障。
- 提供 `fault_active`、`fault_code`。

### 4.5 FSBB Modulator

职责：

- 接收广义占空比。
- 判断 Buck / Buck-Boost / Boost 区域。
- 输出输入桥臂和输出桥臂 PWM 比较值。
- 处理自举刷新。
